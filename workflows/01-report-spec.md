# A단계 — koreport로 문안 확정하기

koreport의 여섯 동작(헤아려라·모아라·묶어라·이어라·솎아내라·다듬어라)을 장표 생산에 맞게 순서를 고정한 절차다. 방법론 본문은 `koreport/`에 있다. **필요한 파일만 읽는다.**

## 0. 착수 판단

- 보고서 유형을 정한다: 기획·방안 / 결과 / 진단 / 실적·계획 / 전략·의결 / 과제 계획서 / 회의 / 안내문.
- 유형별 전용 스킬이 있으면 함께 읽는다.

| 유형 | 함께 읽을 파일 |
|---|---|
| 문제해결형·추진방안형 | `koreport/skills/problem-action-report/GUIDE.md` |
| QSS(현장 개선활동) | `koreport/skills/qss-report/GUIDE.md` |
| 주간업무 | `koreport/skills/weekly-report/GUIDE.md` |
| 회의결과 | `koreport/skills/meeting-report/GUIDE.md` |
| 모든 장표형 보고서(양식) | `koreport/skills/onepage-format/GUIDE.md` — **장표로 낼 때는 항상** |

- 원자료가 PDF·DOCX·PPTX·웹 페이지라면 `ppt-master/scripts/source_to_md.py`로 Markdown으로 바꿔 읽는다(LLM이 원본을 통째로 읽는 것보다 싸다).

## 1. 헤아려라 — 목적 문장 (koreport/references/01, 02)

- 독자와 '독자의 독자', Gain·Pain·Context를 적는다.
- 목적 문장: "이 보고서는 [독자]가 [무엇]을 결정·승인·선택하도록 돕는다."

## 2. 모아라·묶어라 — 메시지 (03, 06)

- Fact → Issue → Recommend로 메시지를 낸다. 각 메시지에 News·Differences가 있는지 묻는다.
- 항목이 넷 이상이면 셋 이하 덩어리로 묶는다.

## 3. 이어라 — 제목·목차·헤드라인 뼈대 (04, 05) ⛔ 사용자 확인

`report_spec.md`의 **머리말(frontmatter)과 `## 장 제목` + `HL:` 줄만** 쓴다. 본문은 아직 쓰지 않는다.

```markdown
---
title: 대상 + 개선 방법 + 목표
toc: 검토 배경 | 현황 및 이슈 | 추진 방향 | 추진 내용 | 종합
---
## Ⅰ. 검토 배경
HL: …
## Ⅱ. 현황 및 이슈
HL: …
```

- 목차는 onepage-format §1의 유형별 목차를 따르고, 회사 양식이 있으면 회사 양식을 쓴다.
- 헤드라인만 이어 읽어도 줄기가 이어지는지 확인한다("필요!" → "그래? ~해줄게!").
- 이 뼈대를 사용자에게 보여 주고 방향을 확인받는다. 가정한 니즈·메시지는 따로 밝힌다.
- 시각화가 메시지를 결정할 장은 이 단계에서 `@ppt-master` **후보**로 표시해 둔다(최종 결정은 B단계).

## 4. 문안 작성 — 묶고–풀기 (05, 06, 07)

- 장마다 `HL:` 키워드를 같은 순서로 본문 묶음(❍)에 풀고, 근거(•)를 붙이고, ☞ 시사점으로 닫는다.
- 결근방과(결론 → 근거 → 방법 → 효과). 모든 주장에 통계·사례·정의 중 하나 이상.
- 자료가 갖춰진 장부터 쓴다. 앞에서 꺼낸 이슈는 뒤의 방안에서 회수한다.
- 문법은 `02-spec-format.md`.

## 5. 솎아내라 — 양식·문장 (08, 09, 10 + onepage-format)

- 장당 13줄 안팎('1131' 배분), 묶음 3개 이하, 불릿 1줄 목표.
- 장의 성격에 맞는 종결어(배경 '~필요', 현황 사실·이슈, 방안 실행형, 맺음 '~하겠습니다').
- 기호 위계를 지킨다(❍ • - ☞ ※ ▷ 【 】). 핵심어만 `**굵게**`(블루).
- 문형·어휘가 막히면 `koreport/skills/sentence-patterns`, `report-vocabulary`를 **필요한 항목만 검색해** 본다(파일이 커서 통째로 읽지 않는다).

## 6. 다듬어라 — 점검 (12)

```bash
python "<RM_DIR>/scripts/spec_to_pptx.py" "<project>/report_spec.md" --check
```

- 점검기가 잡는 것: 헤드라인 누락·과다 길이, '검토·논의·고려'로 끝나는 결론, 줄 수 초과, 표 3개 이상, 1단계 기호 혼용, 묶음 4개 이상, 긴 불릿, ※에 들어간 판단, 현황 장의 '~필요', 남아 있는 `확인 필요`·`○○`·`TBD`, 서술형 종결 혼용.
- 점검기가 못 잡는 것(사람·LLM이 본다): 반려 원인 4가지(끊긴 논리, 무색무취 결론, 말로만 보충, 중언부언), 독자가 던질 질문과 답, 용어 통일.
- 핵심 결함이 해소되면 멈춘다.

## 산출물

- `report_spec.md` — 이후 모든 장표의 단일 원천. 수정은 항상 여기서 한다.
- 가정·미확인 사항 목록 — 사용자에게 따로 알린다.
