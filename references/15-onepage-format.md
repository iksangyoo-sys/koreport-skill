# 15. 1-page 장표 양식 — 유형별 목차, 장표 4층 구조, 기호·종결·한자 약어, 색·표·도형 규칙

> **언제 읽나:** 한국 기업(특히 제조 대기업 사내 보고)의 가로형 1-page 장표 양식으로 초안을 쓰거나 고칠 때, 사용자가 "우리 회사 보고서 스타일로", "개조식으로", "장표 형식으로"를 요청할 때, 기호 위계·종결어·한자 약어·색을 통일해야 할 때 읽는다. 교정 원칙과 전후 사례는 [16-correction-casebook.md](16-correction-casebook.md), 주간업무·회의결과·이메일·제안서 작성 Tip은 [17-report-types-email.md](17-report-types-email.md)에 있다.

이 편은 저자가 학습 자료로 제공한 실제 사내 보고서 장표 약 1,400장(25종 이상 보고서의 수정본·첨삭 노트 포함)을 분석해 정리한 양식이다. 사례 속 회사명·수치·인용은 양식을 보이기 위한 것이므로 실제 근거로 재사용하지 않는다.

## 핵심 원칙

1. **장표 한 장은 4층으로 짠다.** 헤드라인(결론) → 묶음 본문(근거) → ☞ 시사점 → 하단 연결·보충. 헤드라인만 이어 읽어도 보고서 전체 줄기가 보여야 한다.
2. **보고서 유형이 목차를 정한다.** 기획·결과·진단·계획·전략 보고는 목차가 다르다. 회사 양식이 있으면 회사 양식이 우선이다.
3. **장의 성격이 종결어를 정한다.** 배경 장은 '~필요', 현황·진단 장은 사실과 이슈(Fact & Issue), 방안 장은 실행형('~를 선순환', '~로 개편'), 맺음 장만 합쇼체('~하겠습니다')로 쓴다.
4. **기호에는 의미가 하나씩 있다.** ☞는 결론적 시사점, ※는 보충·전제, *는 각주, ▷는 세부 실행·부연, 【 】는 블록 제목. 기호를 섞어 쓰면 위계가 무너진다.
5. **색은 블루 단색 계열로 통일하고 의미가 있을 때만 쓴다.** 강조색은 핵심 메시지와 핵심어에만 쓴다.
6. **도형·표·박스는 줄일수록 좋다.** 박스 안에 박스를 넣지 않는다. 논리관계를 정확히 나타낼 때만 도형을 쓴다.

## 방법과 도구

### 1. 보고서 유형별 목차

| 유형 | 목차 흐름 | 비고 |
|---|---|---|
| 기획·방안(검토 보고) | 검토 배경 → 현황 및 이슈 → 추진 방향 → 추진 내용 → 종합(일정·조직) | 경영층이 가장 보는 곳은 검토 배경과 추진 방향 |
| 결과 보고 | 추진 배경 → 추진 활동(방법) → 활동 결과 → 향후 계획 | '향후 활동 제언'이 아니라 자기 실행 '계획'으로 맺는다 |
| 진단 | 진단 개요 → 진단 결과 → 개선 방안 → 향후 계획 | 진단 개요에 무엇을·누가·언제·어떻게(5W1H) 진단했는지 쓴다 |
| 조직·미션 | 추진 배경 → 미션과 역할 → 추진 방향 → 추진 로드맵 | |
| 실적·계획 | 추진 경과 → 여건 변화 → 개선 방향 및 추진 방안 | 여건 변화 장에는 "한마디로 어떻게 변했고, 시사점은 무엇인가"를 담은 대표 문장 1개 |
| 전략·의결 | 기존 전략 점검 → 환경 변화(고객 / 경쟁사·당사, 3C) → 상세 전략 → 투자 → 토론 아젠다 | 불리한 결과도 숨기지 않는다 |
| 과제(PJT) 계획서 | 추진 배경 → 추진 목표 → 추진 내용 및 계획 → 활용 계획 → 기대 성과 → 추진 일정 및 조직 → 분기 실적 및 향후 계획 | 아래 6절 양식 참고 |
| 사내 안내문 | ○개념 → ○배분·기준 → ○절차(신청→검증→심의→지급) → ○신청 요건 및 방법 → 담당자 → 설명회 일정 → [첨부] 상세 요건 | |
| 회의·위원회 | 첫 장에 시간·내용·발표자 진행표 → 안건별 장 → 토론 주제 | |

**추진 배경과 검토 배경을 구분한다.** 이미 결정된 일의 후속 보고는 추진 배경, 결정을 받으려는 보고는 검토 배경이다. 배경에는 독자가 **중요성**(논리의 강도)과 **시급성**(논리의 전달 속도)을 느낄 내용을 담는다. 시급성은 "경쟁사도 이미 시작했다"가 경영층에 부담 없이 가장 강하다.

**표지:** 날짜('23. 10. 24) + 작성 부서 + 제목 + 목차 키워드 4~5개를 한 장에 둔다. 승인 경로가 필요하면 R(작성)·A(승인)·I(보고 대상)를 적는다. 이사회 안건은 "제n호 보고안건 / 회의명 / 보고부서·보고자"를 쓰고 작성 주체("본 보고안은 ○○ TF 구성을 통해 작성")를 밝힌다.

**보조 장:** 개념 설명은 [참고], 근거 원자료(설문·VOC·상세 절차·커리큘럼)는 [첨부 n]으로 내리고 본문에서 "*첨부1 : …"로 참조한다. 쪽 번호는 우상단 '현재/전체'(1/6). 첨부는 번호를 따로 매긴다.

### 2. 장표 4층 구조

| 층 | 내용 | 형식 |
|---|---|---|
| ① 장 제목 | 'Ⅰ. 검토 배경', 'Ⅲ. 활동 결과 _ 직무별 교과목 체계' | 상단 바, 소제목은 '_'로 붙인다. 범위를 정확히 쓰고, 결과 보고는 결과를 제목에 담을 수 있다 |
| ② 헤드라인 | 결론 1~2줄, 장표 폭의 2/3 이상 | 블루, 아래 가는 선. 짧으면 키워드 구체화·목적/수단 추가·묶고–풀기 점검으로 늘린다 |
| ③ 묶음 본문 2~3개 | 묶음 첫 줄 = 묶는 문장, 아래 줄 = 근거(풀기) | 라벨형("현황 :", "니즈 :", "실태 :") 또는 괄호 소제목형("(신규채용) …") |
| ④ ☞ 시사점 | 묶음마다 판단·필요로 닫는다 | 장 안에서 ☞ 패턴 통일. 배경색을 넣으면 구분선 역할도 한다 |
| ⑤ 하단 줄 | 다음 장 연결·보충·인용 | 따옴표 문장. 아래 '하단 박스의 용도' 참고 |

**'1131' 줄 배분:** 헤드라인 1 + 서브라인 1 + 박스 본문 3~4 + 부연 1 = 6~7줄. 장표를 상하 1:1로 나누면 장당 13줄 안팎이 된다. 박스 안이 6줄을 넘으면 ※ 줄은 박스 밖으로 뺀다.

**서브라인:** 헤드라인보다 한 단계 낮춘다. 헤드라인의 What을 대상별로 나누고 대상마다 How를 붙인다.
- 예: "그룹공통 과정은 똑같이, 밸류체인 직무과목은 모두 함께, 현장 실무교육은 회사별로 따로"

**하단 박스의 용도:** 사례 보고서들은 장 하단에 따옴표 문장을 둔다. 첨삭 노트는 그 용도를 이렇게 정한다.
- 하단 박스(Take-away)에는 본문에 쓰지 못한 추가 사항, 다음 장 암시, 참고 사항을 둔다.
- **장의 결론은 헤드라인에 둔다.** 하단에 결론을 따로 적어 헤드라인과 겹치게 하지 않는다.
- 현황 장의 마지막 줄은 다음 장(추진 방향)으로 넘기는 연결 문장이다. 헤드라인끼리 "필요!" → "그래? ~해줄게!"처럼 대화로 이어져야 한다.
- 색 박스가 많으면 하단 박스의 색을 빼고 따옴표 텍스트로 처리한다.

**VOB·VOC 인용:** 화자를 괄호로 밝히고 출처와 날짜를 붙인다. "(경영층) …", "(직원) 수율과 품질 문제가 눈에 보이나, 해결 방법은 몰라…" (사업점검회의, 8.2). 사내 VOB와 최고경영자 어록처럼 성격이 다른 인용은 분리한다. 비슷한 VOC는 하나로 합치고 별도 박스로 뺀다.

### 3. 기호 체계

| 단계·용도 | 기호 | 규칙 |
|---|---|---|
| 장 제목 | Ⅰ. Ⅱ. Ⅲ. | 로마숫자를 장 제목과 본문 분류에 함께 쓰지 않는다 |
| 1단계 | ❍ 또는 ■ | 묶음 문장. 핵심어는 블루 |
| 2단계 | • | 근거·세부 |
| 3단계 | - | 하위 근거·예시. 하위 내용은 최대 3개 |
| 각주 | *, **, 1), 2) | 본문 단어 뒤에 표시하고 같은 장 하단에서 푼다. 비중이 작은 설명을 내릴 때 쓴다 |
| 보충 | ※ | 참고·전제·부차 정보. 불릿이 아니므로 핵심 문장에 쓰지 않는다 |
| 시사점 | ☞ | 결론적 판단. 묶음 끝 |
| 부연 | ▷ | 세부 실행항목, 지표 띠("▷ 지표 1. … (50%) : '15년 無 → '16년 2件") |
| 예시 | 例), 예) | ▷ 대신 '(예)'로 표시 |
| 블록 제목 | 【 】 | 표·박스·도형 제목. 그림 캡션은 [ ] |
| 고유 명칭 | 「 」『 』 | 과정명·제도명·프로세스 연쇄(「KPI선정→목표수립→문제해결→관리」) |
| 번호 | ①②③, ❶❷❸, 사각 배지 1 2 3 | 순서·연계가 있을 때만. 순서 없는 병렬은 점 불릿. 한 장에서 같은 번호 기호를 다른 용도로 겹쳐 쓰지 않는다 |
| 연결 | → ⇒ ← ↔ ｜ | 인과·전환 / 영향 / 역인과 / 대비 / 한 줄 내 구분 |
| 증감 | ↑ ↓ ↗ ↘ △ ▲ | 표 헤더에 ↗↘를 붙여 방향을 보인다. 비율 차이는 %p |
| 선택 | ■ / □ | 체크박스(성격 ■정량 □정성) |
| 대응 | → (단기 案) / → (장기 案) | |

**줄간격:** 100%가 기본, 묶음 사이는 120~150%.

### 4. 문장 형태

**종결:** 명사형 개조식으로 끝낸다. 한 보고서 안에서 종결 패턴은 한두 가지로 통일한다(서술형 '~함·~됨'과 체언 종결을 섞지 않는다).

| 장 | 종결 예 |
|---|---|
| 배경 | ~필요, ~시급, ~서둘러야 할 시점, ~니즈 有 |
| 현황·진단 | 사실·수치 + 이슈. '~필요'(권고)를 쓰지 않는다 |
| 방안 | ~를 선순환, ~로 개편, ~구축, ~운영, ~추진 |
| 계획 | ~(~'24.12), ~完, ~예정(효과·조건과 함께) |
| 맺음 | ~하겠습니다 |
| 제안서 요약 | ~하고자 함. |

**한자 약어(사례 보고서에서 쓰는 것):**
- 시간·전후: 中, 前, 後, 時, 上/下(반기), 末, 初, 以前/以後, 先/後(先수주 後투자)
- 범위·관계: 內, 外, 間, 別, 比, 對, 向(○○向), 用(EV用), 下(코칭 下), 順
- 존재·정도: 旣, 未, 有, 無, 多, 少, 高, 低, 大, 小, 弱, 强, 存, 超
- 가능·판단: 可, 難, 不可, 要, 必, 完
- 범위 지정: 全, 各, 例, 現, 新, 再
- 접미: 化(PJT化, 교재化), 型, 業, 場, 社, 件, 院
- 지역 약칭: 浦·光(포항·광양), 兩所

한자 약어는 해당 조직이 이미 쓰는 경우에만 쓴다. 외부 독자·메일·서술형 문서에는 쓰지 않는다.

**라벨 균등배치:** 2음절 라벨은 띄워 폭을 맞춘다. (채 용) (평 가) (교 육), 목 적 :, 구 분.

**문장 길이:** 한 줄 40~70자. 주어를 생략하고 2~3절을 쉼표로 잇는다. 불릿 하나는 1줄을 목표로 하고, 두 줄이 되더라도 한 줄처럼 읽히게 쓴다. 3줄을 넘으면 중간을 잘라 방법→결과, 문제→원인으로 구조화한다.

**주제 제시형:** 전략 보고서는 "천연흑연은, …", "R&D는, …"처럼 주제를 앞세운다. 라벨·핵심 키워드는 문장 앞에 둔다("(당사관점) WP제품 홍보를 통한 …").

**표기:**
- 연도 '23, '25.1Q, 12/E(말), '23.下. 한 장 안에서 날짜 표기를 하나로 맞춘다.
- 큰 수는 줄인다(11,000건 → 11천건, 9,300억원 → 9.3천억원, 27.7억원 → 28억).
- 비율 나열은 ':' 대신 '·'(채권 4%·주식 62%·대체투자 34%).
- 기업명·인명은 한글, 괄호에 영문. 영문 약어는 대문자, 단위는 소문자. 약어는 첫 등장 시 풀어 쓰거나 장 하단에서 일괄 정의한다.
- 직함·고유명사·과제명은 문서 끝까지 같은 표기(인재창조원/인창원, PJT/프로젝트 혼용 금지).
- 실명은 김ㅇㅇ로, 미확정 수치는 확정 전에는 넣지 않거나 "확인 필요"로 둔다.

### 5. 논리 장치

- **인과 화살표 체인:** "도제식 OJT에 의존하여 → 암묵지가 많고, 개인 노하우 위주의 역량 형성으로 → 직원간 편차 有". 화살표 사이에 접속어를 넣으면 문장으로 읽힌다.
- **대비:** As-Is / To-Be, 기존 / 향후, (現) → (개정), AS-WAS(~'19) / AS-IS('20~), 요청 사항 / 대응 방안, 현상 ‖ 대응방안. 대구 라벨을 정확히 맞춘다('현행–개선'이 아니라 '현재–향후', '문제–개선'). 비교 항목은 가운데 축에 두고 양쪽을 대칭으로 둔다.
- **문제 진단:** 현상·문제점 → 근본원인 → 개선방향. 문제 = 목표수준 – 현재수준.
- **정량 근거:** 비율과 실수 병기("全 직원의 60%(92명)"), 내부 기준 비교("인당 6.5시간/年 (본사 97.7시간/年)"), 추이("'20년 1.7% → '22년 4.3%"), 실적/목표(달성률), 단위·기준 시점("('23.9/E 기준, 단위: 명)"), 산식과 전제("작성전제 - …"), 데이터 출처("Data Source: MES").
- **벤치마킹:** 경쟁사 사례 → "우리도 …" 시사점. 벤치마킹 대상은 비교표 왼쪽 열.
- **프레임:** 3대 방향 7개 과제, Right People / Right Skill / Right Solution, 기본 알기 → 제대로 하기 → 더 잘하기, Plan-Do-See, 단기/중기/장기 × 과제 매트릭스, 방안별 위협/기회.
- **대구 문장:** "그룹공통 과정은 똑같이, 밸류체인 직무과목은 모두 함께, 현장 실무교육은 회사별로 따로". 운율(3-4-3-4)로 끊어 쓰면 귀에 남는다: "수행기간은 확 줄이고 / 성과는 쭉 올리고 / 갑의식은 버리고".
- **추진 방향 헤드라인의 감각어:** 추진 방향은 추진 내용에 일관되게 적용되는 관점과 철학이다. 여기에는 '촘촘히·두텁게' 같은 순우리말 부사를 쓸 수 있다. 단, 그 실체를 각주에서 명사·동사로 정의한다("*촘촘히 : 全 소재사에 동등한 수준의 교육을 빠짐없이 제공"). 이것이 헤드라인에서 '형용사·부사를 쓰지 않는다'의 유일한 예외다(맺음말 합쇼체 문장의 운율은 [16편](16-correction-casebook.md) 5절 참고).

### 6. 과제(PJT) 계획서 양식

| 장 | 구성 |
|---|---|
| 표지 | 날짜, 부서, PJT 리더, □ PJT명, □ 기간 |
| 추진 배경 | 목적 / 추진 방향 / 현황 및 문제점(원인 → 대책, 하위 줄에 수치) |

### 7. 색·글꼴

| 역할 | 색 | 쓰임 |
|---|---|---|
| 본문 | #000000 | 기본 텍스트 |
| 강조 1 | #0000CC / #0033CC | 헤드라인, 본문 핵심어 |
| 강조 2 | #002060 / #1F497D | 하단 따옴표 문장, 진한 제목 |
| 바·배지 | #0070C0 / #1180AE / #05507D | 상단 타이틀 바, 번호 배지, 표 헤더 |
| 보조 면 | #C1DDF0 / #CDE6FF / #D9ECF7 / #EEEEEE | 박스 바탕, 라벨 박스 |
| 경고 | #FF0000 / #C00000 | 수정 표식. 본문에는 거의 쓰지 않는다 |

- 색은 두 경우에만 쓴다. ① 의미를 부여할 때(직군별 색, 같은 계열 명도로 Low/High). 3색 이상이면 범례를 적는다. ② 부각할 대상만 팝업시킬 때. 5~6색을 쓰거나 빨간 선을 넣으면 균형이 깨진다.
- 위계가 다른 항목은 색으로 레벨을 표현한다(같은 레벨은 블루, 다른 레벨은 그레이).
- 위는 가볍게, 아래는 무겁게 칠한다. 앞 단계를 진하게 칠하면 정작 중요한 뒤 단계가 묻힌다.
- 그라데이션은 순서를 표현할 때만 쓴다('많음' 쪽을 진하게). 병렬 박스는 같은 색. 의미 없는 그라데이션·그림자·3D·스티커 효과는 지운다.
- 비교 기준이 다른 두 그래프에는 다른 색을 쓴다. 의도하지 않은 빨강은 강조로 읽힌다.
- 글꼴: 맑은 고딕 중심. 본문 12~14pt, 헤드라인 15~16pt, 각주 9~10.5pt. 결론·핵심은 14pt로 박스 위에 둔다. 위계는 폰트 크기로 차등한다(현상·원인은 작게 한 줄, 개선방향은 크게).

### 8. 표·도형·이미지

**표**
- 장당 1~2개. 본문 표의 항목은 3~4개. 행 하나를 빼면 의미가 무너지고 하나를 더하면 거추장스러운 상태가 간결한 표다.
- 외곽선과 좌우·내부 세로선을 지우고, 내부 선은 0.25pt 옅은 회색. 텍스트는 왼쪽, 숫자는 오른쪽 정렬.
- 의미 없는 헤더 행·열('구분', 합계 행)을 지운다. '구분'은 실제 축 이름으로 바꾼다. 조건 설명은 표 제목으로 올린다.
- 핵심 수치가 표 맨 아래에 묻혀 있으면 위로 올리거나 파이·막대로 바꾼다. 3개 이상 항목 비교는 그래프보다 표가 읽기 쉽다.
- 항목이 하나뿐인 표는 아이콘으로 바꾼다. 텍스트 표는 '구분'을 가운데 둔 As-Is/To-Be로 바꾼다. 수학공식 형태는 피한다.

**도형**
- 박스+박스, 박스 안의 박스를 피하고 문장으로 쓴다(언박싱). 사각형이 많으면 ① 합치고 ② 지우고 ③ 언박싱한다.
- 도형은 헤드라인의 사고 흐름과 문장 구조를 그대로 따라야 한다. 좌→우 흐름은 우향 도형으로, 도형 번호와 설명 번호는 일치시킨다.
- 인과로 오독될 도형(삼각형, 엉뚱한 곳에서 뻗는 화살표)은 지운다. 연결 도형은 분석 대상을 정확히 가리킨다.
- 선은 0.25pt, 도형 크기 통일, 화살표는 가늘고 단순하게. 연결고리 유형은 하나로, 도형 사이 틈은 붙인다. 원·사각·삼각형을 섞지 않는다.
- 도형 면적은 메시지의 무게에 비례한다. 면적은 큰데 메시지가 약한 그래프·조직도는 지운다. 빈 공간을 채우려고 새 내용을 넣지 않는다.
- 헤드라인 핵심어는 본문 도형으로 증명한다('선순환'이면 원형 도형).
- 같은 레이아웃만 반복하면 단조롭다. 같은 패턴 반복은 비교를 쉽게 할 때 쓰고(연도별 하단을 같은 항목으로), 메시지가 다른 블록은 다른 구조로 그린다.

**배치**
- 좌우는 비교할 때, 상하는 비교가 필요 없을 때, 흐름은 절차·시간을 보일 때 쓴다.
- 한쪽만 꽉 차면 상하를 좌우로 바꾼다. 좌우 여백과 오·행 정렬을 맞춘다.
- 정의와 조치, 감점 정의와 감점 사례처럼 관련 문장은 붙여 둔다. 번호로 연결되는 대상은 '一'자로 읽히게 바짝 붙인다.
- 독자의 시선은 텍스트보다 도형·그림에 먼저 간다. 핵심이 아닌 그림(지도 등)이 시선을 빼앗으면 줄이거나 톤을 낮춘다.

**이미지**
- 크기를 통일하고 캡션은 이미지 위나 안에 [ ]로 넣는다. 표와 이미지가 따로 있으면 하나로 합친다. 이미지로 복사해 붙이지 않는다(해상도 저하).
