# 교정 사례집 — 교정·교열·윤문 원칙과 Before→After

> **언제 읽나:** 사용자가 초안을 주며 "고쳐줘", "다듬어줘", "교정·교열·윤문해줘", "첨삭해줘"라고 할 때, 여러 부서 자료를 모아 종합 보고서로 편집할 때, 고친 이유를 원칙과 함께 설명해야 할 때 읽는다. 장표 양식(목차·기호·색·표)은 [onepage-format 스킬](../onepage-format/SKILL.md), 반려 원인 진단과 퇴고 절차의 일반론은 `koreport-skill`의 [12-revision.md](../../references/12-revision.md), 문장 압축과 정확성은 [09](../../references/09-sentence-concise.md)·[10](../../references/10-sentence-accurate-clear.md)편에 있다. 주간업무·회의결과·이메일 등 유형별 교정은 `skills/`의 전용 스킬을 본다.

이 편은 저자가 실제 사내 보고서를 첨삭한 기록(같은 장표의 여러 수정본, 슬라이드 노트의 강평, 교정의견 장표)에서 반복되는 교정 원칙을 뽑아 정리한 것이다. 사례 속 조직명·수치는 교정 방식을 보이기 위한 것이므로 근거로 재사용하지 않는다.

## 핵심 원칙

1. **구조부터 고치고 문장은 나중에 고친다.** 헤드라인과 본문이 어긋난 장표의 문장을 먼저 다듬으면 그 수고가 버려진다. 순서는 구조 → 문장 → 표기 → 디자인 → 수치 대조다.
2. **현황·이슈는 질문이고, 방향·내용은 답이다.** 앞에서 던진 이슈마다 뒤에 답이 있어야 한다. 짝이 맞지 않으면 답에 맞게 질문을 바꾸든, 질문에 맞게 답을 바꾸든 반드시 맞춘다.
3. **보고서의 중심은 News & Differences다.** 경영층이 읽을 거리는 기존에 없던 것(신규·교체)과 기존과 달라진 것(추가·축소·대체)이다. 현황 나열에 가까운 문장은 지우거나 첨부로 보낸다.
4. **중복은 무조건 지운다.** 아무리 매력적인 메시지라도 같은 장, 다른 장에서 의미가 겹치면 하나만 남긴다.
5. **느낌어는 수치와 원인으로 바꾼다.** '저조', '미흡', '큼'은 사람마다 다르게 읽힌다. 측정할 수 있으면 수치로, 측정하지 못했으면 '有'처럼 중립어로 낮추고, '불비'처럼 결과만 말하는 단어는 원인을 쪼개 묘사한다.
6. **작성자의 내용은 존중하고, 고친 이유는 원칙으로 댄다.** 약편집에서는 수치·일정·핵심 내용을 바꾸지 않는다. 고칠 때마다 어떤 원칙 때문인지 한 줄로 밝힌다.

## 방법과 도구

### 1. 교정 절차

| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| ① 구조 | 헤드라인만 이어 읽기, 장별 목적 확인, 이슈↔답 짝 맞추기, 장 간 중복 제거 | 헤드라인 1개에 메시지 1개, 장 1개에 목적 1개 |
| ② 문장 | 장 성격에 맞는 종결, 느낌어 → 수치·원인, 수동 → 능동, 군더더기 삭제 | 문장 하나가 그 자체로 완결되는가('뭐지?' 질문이 남지 않는가) |
| ③ 표기 | 용어·약어·고유명사·날짜·단위 통일, 기호 위계 | [onepage-format](../onepage-format/SKILL.md) 기호·표기 규칙 |
| ④ 디자인 | 박스·색·도형 줄이기, 줄 수(장당 13줄 안팎), 좌우 균형 | 도형 면적이 메시지 무게에 비례하는가 |
| ⑤ 수치 대조 | 헤드라인 수치 ↔ 본문·표 수치, 합계, 반올림, 연도 | 원본과 한 자리라도 다르면 원본을 따른다 |

교정 결과를 돌려줄 때는 고친 문장과 함께 **원칙 한 줄**을 붙인다. 사용자가 다음 초안에서 같은 실수를 스스로 잡게 하기 위해서다.

### 2. 스토리·논리 교정 원칙

1. 헤드라인 하나에 메시지 하나만 둔다. 나머지 메시지는 박스별 서브 메시지로 내린다.
2. 헤드라인은 본문의 요약이어야 한다. 헤드라인 키워드가 본문에 없거나(예: 헤드라인은 '인간존중·개선문화', 본문엔 관련 내용 없음) 본문 핵심어가 헤드라인에 없으면 고친다.
3. 헤드라인과 서브 헤드라인의 레벨을 맞춘다. 헤드라인이 구체 수치이고 서브가 상위 개념이면 레벨링 오류다.
4. 장의 제목과 헤드라인의 성격을 맞춘다. 'OO 니즈' 장(이슈 장)에 대안을 말하는 Recommend형 헤드라인을 쓰면, '주체가 ~을 희망/필요/기대'하는 니즈형 문장으로 바꾼다.
5. 한 블록 안에 Fact·Issue·Recommend를 섞지 않는다. Fact → Issue 순으로 쓰고, Recommend는 블록 아래 ☞ 시사점으로 올린다.
6. 앞장 이슈에 정면으로 답하고 앞장 내용을 되풀이하지 않는다. 리드메시지는 배경 → 방향 → 결론으로 잇는다.
7. 대비 축은 같은 차원으로 맞춘다(사람 vs 시점, 해외 vs 국내를 섞지 않는다). 유사한 기간·대상끼리 모은다.
8. 한 문장에 목적 하나만 둔다. '~을 위해서는 ~을 위한' 같은 이중 목적문은 끊는다.
9. 한 장에 목적 하나만 둔다. 1페이지를 채우려고 끼워 넣지 말고 장을 나눈다. 주제와 관련 없는 블록은 지운다.
10. 수단에는 '왜'를 붙이고, 절차 장에는 '왜 이 절차인가'를 넣는다. 지침화·규정화 같은 후속 절차보다 본질적 개선 내용을 쓴다.
11. 번호로 연결한 대상은 같은 방향으로 배열한다. 추진방향 1·2·3은 좌→우인데 4만 아래에 있고, 추진내용 1~4는 위→아래라면 번호의 연결 의도가 사라진다.

### 3. 문장 전개 유형과 중복 처리

문장은 what(결론)·why(근거)·how(방법)·so what(다음 활동·효과)을 조합해 쓰고, Leveling과 MECE를 지킨다.

| 유형 | 전개 | 쓰는 곳 |
|---|---|---|
| 수평(another) | what → another what, how → another how … | 같은 레벨 항목을 나란히 늘어놓을 때. 서술 패턴을 통일해 병렬로 쓴다 |
| 수직(specific) | what → how, what → so what, how → specific how … | 한 항목을 아래로 파고들 때. 역시 서술 패턴을 통일한다 |

**장 간 의미 중복을 풀 때**
- **대체:** 문장 유형을 바꾼다. 2쪽의 '무엇을 → 어떻게'(what → how)가 4쪽 내용과 겹치면 2쪽을 '무엇을 → 그래서'(what → so what)로 바꾼다.
- **제거·세분화:** 겹치는 부분을 지우고, 남은 키워드를 앞뒤 스토리로 늘려 쓰거나 한 단계 더 쪼갠다(어디서·무엇으로 등 where·with what으로 세분화).
- 바꾼 뒤 다른 장과 또 겹치지 않는지 다시 본다. 남은 중복은 연결어 정도로 톤을 낮춘다.

### 4. 수합 자료 편집 — 약편집과 강편집

여러 부서 자료를 모아 종합 보고서를 만들 때 쓴다.

| 스타일 | 언제 | 고쳐도 되는 것 | 고치면 안 되는 것 |
|---|---|---|---|
| 약편집 | 부서별 실적·계획 수합 보고 | 중복 워딩, 불릿, 글꼴·크기, 선·도형, 분량 균형, 작성 패턴 통일 | 핵심 내용, 품질·금액·인원 수치, 일정, 투입 자원 |
| 강편집 | 기획성 보고(부서 자료를 재료로 새 방안을 만들 때) | 재조합, 새 내용 착안·추가 | 착안한 내용은 해당 부서와 협의해 실행 가능성을 확인한 뒤 확정 |

**강편집 5단계** (예: 부서별 24줄 → 13~15줄)
1. **그룹핑:** 부서 관점을 버리고 유사성·연관성 기준으로 2~3개 카테고리로 묶는다(신입·경력 / 직책자 등).
2. **정제:** 보고서 주제·추진방향 범위 밖이거나 거리가 먼 내용, 중복은 지우거나 다른 항목·첨부로 옮긴다.
3. **발췌:** News & Differences에 기여하는 내용만 본문에 남긴다.
4. **착안:** News & Differences가 없으면 5W2H·4M1E 등으로 원본을 구체화해 키워드를 찾고 새 내용을 착안한다.
5. **구조화:** 발췌·착안 내용을 이어 스토리를 짜고, 묶고 풀기 원칙으로 구조화한다.

**News & Differences 판별**

| 구분 | 종류 | 뜻 |
|---|---|---|
| News | 신규 | 기존과 별개로 새로 만든 것 |
| News | 교체 | 기존 것을 없애고 새것으로 바꾼 것 |
| Differences | 추가 | 기존에 다른 것을 더한 것 |
| Differences | 축소 | 기존의 일부를 없앤 것 |
| Differences | 대체 | 기존 일부를 없애고 다른 것으로 채운 것 |

### 5. 문장 교정 원칙

**적확한 단어, 능동문, 운율**
- 고유명사·외래어는 한 가지로 쓴다(정식 명칭과 약칭, 'PJT'와 '프로젝트'를 섞지 않는다). 기업명·인명은 한글로 쓰고 ( ) 안에 영문을 쓴다. 영문 약어는 대문자, 영문 단위는 소문자.
- 동사는 다양하게 쓴다(향상·제고·증가·상승).
- 시간·장소·방향·방식·정도를 꾸미는 형용사·부사는 피한다('쾌적하고 깨끗하며 매우 편안한 공간' → '쾌적한 공간'). '곧, 매우, 상당히, 약간'은 수치와 사례로 바꾼다.
- 지시어(이것, 그것, 이렇게)는 줄인다. '~수', '~것', '~있는' 세 가지만 지워도 문장이 짧아진다('없앨 수 있는 것을 모두 도출' → '모두 도출').
- 능동문으로 쓴다('계획이 수립되었다' → '계획을 수립했다'). 출처가 불분명할 때만 수동문을 쓴다.
- 긍정문으로 쓴다. 부정의 부정으로 긍정을 표현하지 않는다('중요한 이슈가 아니라고는 못할 것이다' → '중요한 이슈다'). 요청은 기한을 넣은 긍정형으로 바꾼다.
- 쉬운 단어와 우리말 운율(3-4-3-4 / 3-5-4-3)을 살린다. 두 문장은 짧게, 세 번째는 길게 리듬을 준다('PJT 성과창출은 향상시키고' → '성과는 쭉 올리고'). 단, 이런 감각어는 맺음말 같은 합쇼체 문장에서만 쓰고 본문 개조식과 헤드라인에는 쓰지 않는다(추진방향 헤드라인의 예외는 [onepage-format](../onepage-format/SKILL.md) 5절).

**느낌어와 원인**
- '참여율 저조'처럼 지표를 느낌어로 쓰면 조사가 부족했다는 고백이 된다. 지표는 수치로 쓴다.
- 측정할 길이 없는 것(암묵지의 양)은 느낌어를 쓰되, 측정할 수 있으나 못 한 것은 '큼' 같은 선정적 단어 대신 '有'로 낮춘다.
- '학습여건 불비로 교육을 충분히 못함'은 인과처럼 보이는 의미 중복이다('36도라서 덥다'). 여건을 쪼개 묘사하고 원인을 밝힌다.

**그 밖의 문장 원칙**
- 시급성은 어조로 드러낸다('필요' → '서둘러야 할 시점', '지속' → '조기에').
- 추상어는 구체 명사로 바꾼다('인프라 미흡' → '교육장, 숙소 부족'). 막연한 목적 대신 사용 장면을 열거하고 '可'로 맺는다.
- 괄호 보충은 '~하되'절로 흡수하거나 ※·*로 내린다. 각주에 숨긴 핵심은 본문으로 올린다.
- 병렬은 대칭으로 맞추고 반복어 빈도를 줄인다. 헤드라인·표 라벨·본문의 용어를 일치시킨다.
- 독자 조직의 분류와 명칭으로 바꾼다(내부 직급 코드 → '신규채용자·직무전환자').
- 근거 없는 확정 표현은 '검토'로 낮추고 협의처를 괄호로 밝힌다. 인용은 더 상위 권위로, 출처와 날짜를 붙인다. 부정 사례는 뺀다.
- 큰 수치는 헤드라인에서 반올림한다(27.7억원 → 28억원). 본문·표에는 원래 수치를 둔다.
- 부정어는 중립어로 바꾼다('산식/Data 오류, 기여도 축소' → '재무검증, 기여도 조정').

**정확한 단어 교정표**

| 사례 | 교정 |
|---|---|
| 이자는 3% 미만 | 이율은 3% 미만 |
| 고객의 관심 高 | 고객의 관심 多 |
| 토익스피킹 7급에 합격 | 토익스피킹 7급 시험에 합격 |
| 참가 혜택 | 참가자 혜택 |
| 가동 시간은 (특정 시점) | 가동 시각은 |
| 연 30일 이용 | 연간 30일 이용 |
| 추가적인 장비는 | 추가 장비는 |
| ~과의 협업을 통해 | ~과 협업하여 |
| 제품의 성능에 있어서 | 제품 성능에서 |
| 품질에 대하여 | 품질을 |
| 품질 불량으로 인해 | 품질불량 때문에 |
| 2억원이 투자되었다 | 2억원을 투자했다 / 투자금액은 2억원 |
| 보여집니다 | 보입니다 |
| 전문가들로 구성된 회의체 | 전문가들로 회의체를 구성 |
| 주어진 직무에 | 맡은 직무에 |
| 매뉴얼의 도움을 받았다 | 매뉴얼을 활용했다 |

### 6. 디자인 교정 원칙

- 가독성 높이기란 핵심 키워드(독자의 관심, 지시사항)가 도드라지게 하는 일이다. 키워드의 데이터는 구체적으로, 가능하면 그래프로 보인다. 항목명이 길면 가로막대가 맞다.
- 키워드를 받치지 않는 그림(지도 등)이 시선을 빼앗으면 줄이거나 지운다. 독자는 그림을 먼저 본다.
- 본문 도표는 항목 3~4개가 적당하다. 상징성이 약한 항목은 뺀다. 행·열 하나를 빼면 설명이 안 되고 하나를 더하면 거추장스러운 상태가 간결한 도표다. 합쳐도 되는 행은 합친다.
- 표의 선은 모두 지우고 꼭 필요한 곳에만 넣는다. 장당 표는 1~2개. 텍스트 표는 As-Is/To-Be로 구조화하고, 비교 항목(구분)을 가운데 두면 비교가 보인다.
- 헤드라인 바로 아래 본문 전체를 한 박스로 감싸지 않는다. '1131'(헤드라인 1줄 + 서브 1줄 + 본문 3~4줄 박스 + 부연 1줄)로 상·하단을 쓰면 장당 13줄 안팎이 된다. 15줄이 넘으면 줄인다.
- 한쪽이 표로 꽉 차고 반대쪽이 비면 상하 배치를 좌우로 바꾼다. 상부가 무겁고 하부가 부실하면 불안정해 보인다.
- 의미 없는 그라데이션·3D·그림자는 지운다. 박스와 색을 줄이고 핵심 메시지는 따옴표 텍스트로 쓴다.
- 읽는 순서는 위 → 아래, 쉬운 것 → 어려운 것. 관련 문장은 붙이고, 성격이 다른 정보는 떼어 놓는다.

### 7. AI에 헤드라인 초안을 맡길 때

저자는 헤드라인 초안을 AI에 맡길 때 다음 형식으로 요청했다.

> "OO 추진방향 슬라이드의 헤드라인을 작성해줘. 다음 N개의 중점 추진업무를 연결하여 15단어 내외로, 내가 골라 쓸 수 있도록 3개를 추천해줘. 형용사와 부사는 쓰지 말고, 목적 지향적 명사나 동사로 종결해줘."

규칙은 셋이다. ① 하위 항목을 연결해 15단어 안팎으로 쓴다. ② 형용사·부사를 쓰지 않는다. ③ 목적 지향적 명사·동사로 맺는다. 3안을 받은 뒤 사람이 고르고, 추진방향 슬로건처럼 감각어가 필요한 곳에서만 사람이 감각어를 더한다(정의는 각주로 단다. [onepage-format](../onepage-format/SKILL.md) 5절 참고).
