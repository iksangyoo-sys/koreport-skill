# QSS 개선활동 보고서 작성 스킬

QSS(현장 개선활동) 보고서를 쓰거나 교정할 때 쓰는 스킬이다. 실제 교정 노트 6건(개선리더 운영이슈, 발생원 제거 유지관리, 실질측면 QSS 활동 분석·My M&S 진단, 현장 개선활동 동기부여, 프로젝트컨설팅 실행계획, 컨설턴트 현황)의 Before → 교정의견 → After에서 반복된 원칙만 뽑았다.

보고서 일반 방법론(독자 니즈, 메시지 도출, 묶고–풀기, 문장 교정 등)은 `koreport-skill`을 따른다. 이 스킬은 그 위에 **QSS 보고서에서 반복적으로 지적된 것**을 얹는다.

---

## 0. 작업 순서

1. **보고 유형 확인**: 아래 1장의 유형 중 무엇인지 정한다. 경영층 지시·멘토링 발언이 있으면 출처(누가, 언제)를 확보한다.
2. **목차 프레임 확정**: 현황·이슈의 꼭지(예: QSS+ / 제안 / 노하우)를 정하고, 대응방안·향후계획도 **같은 꼭지, 같은 순서**로 간다.
3. **장별 헤드라인 먼저 작성**: 장표 본문보다 헤드라인을 먼저 쓴다. 헤드라인만 이어 읽어도 보고 전체가 이해되는지 확인한다.
4. **본문 작성**: 장표당 하나의 흐름(One slide, one flow). Fact는 이슈를 받치는 근거로만 쓴다.
5. **교정 체크리스트(7장)로 셀프 리뷰** 후, 수정 내역을 Before → After로 정리해 보여준다.

교정 요청을 받으면 장표마다 `교정의견(번호 목록) → 수정안(After)` 형식으로 답한다. 교정의견은 "무엇이 문제인지 → 왜 문제인지 → 어떻게 고칠지" 순으로 쓴다.

## 1. QSS 보고서 유형과 표준 구성

| 유형 | 표준 목차 | 핵심 질문 |
|---|---|---|
| 운영이슈·대응방안 | 1. 경과 → 2. 현황 및 이슈 → 3. 대응방안 | 무엇이 문제이고, 우리는 어떻게 하겠다는가 |
| 제도 개선(동기부여·보상 등) | Ⅰ. 검토배경 → Ⅱ. 경과·이슈 → Ⅲ. 개선방안 → Ⅳ. 향후계획 | 왜 지금 바꿔야 하고, 무엇을 어떻게 바꾸는가 |
| 활동 방향·운영방안(혁신공장만들기 등) | Ⅰ. 현황 → Ⅱ. 관점 전환(As-Is/To-Be) → Ⅲ. 운영방안(절차) → Ⅳ. 향후 일정·대상 | 어떤 관점으로 바꾸고, 어떤 절차로 운영하는가 |
| 진단결과 보고(충실도·My M&S 수준진단) | 진단개요(목적·대상·항목) → 단계별 결과 → 종합의견 → 보완방향 | 어디가 약하고, 무엇을 보완하는가 |
| 연간 실적·실행계획 | Ⅰ. 실적(성과·반성) → Ⅱ. 여건변화 → 중점방향 → 과제별 실행계획 → 일정 | 작년의 반성이 올해 계획으로 어떻게 이어지는가 |
| 첨부: 발생원 분석 양식 | 공장명/공정명/공장장/담당 FT → 활동방향 → 발생원 → 공정별 상세 발생원 → 발생원 제거 방향 | 근본 발생원이 무엇이고, 어떻게 없애는가 |

**구성 원칙**
- **분량 균형**: 현황·이슈가 3장인데 개선방안이 1장이면 균형이 깨진다. 개선방안 2장 + 향후계획 1장처럼 무게를 맞춘다.
- **개선방안과 향후계획은 한 제목으로 묶지 않는다.** 향후계획을 지면 채우기용으로 끼워 넣지 말고 별도 장에 쓴다.
- **향후계획은 앞 장의 개선방안과 같은 아젠다·같은 순서**로 쓴다(개선방안이 2개면 계획도 2개). 내용은 Plan–Do–Check–Action 흐름으로 짜고, 이행 모니터링·피드백까지 구체화한다.
- **목표가 먼저** 나온다. "활동체계 재정립 → KPI 연계 → 동기부여" 같은 수단 나열보다 목표·지향점을 앞에 둔다.
- **빈 공간을 다짐·각오 멘트, 억지 VOC, 의미 없는 조직도로 채우지 않는다.** 검토가 부족하다는 인상을 준다. 남는 공간은 근거 데이터나 실행 구체화로 채운다.
- **개선방안이 여러 개(5개 이상)면** 마지막에 한 장으로 다시 요약한다. 상단에 개선방안 전체 요약을 한 줄로 두는 것도 좋다.
- **같은 보고서의 버전업**(9/17 → 9/18 등)에서는 수치 출처, 기준(전사/광양소), 단위 표기가 버전 사이에 어긋나지 않는지 확인한다.

## 2. 헤드라인 원칙

QSS 교정의견에서 가장 많이 나온 지적이다.

### 2-1. 헤드라인에는 Fact가 아니라 Issue(또는 의견)를 쓴다
- "~시행 中", "총 000건에 대해 000억원 포상", "~하고 있음"은 **현황**이다. 검토배경·이슈 장의 헤드라인은 **왜 이 보고서를 쓰는가(Why)**를 말해야 한다.
- 현황 수치는 헤드라인 바로 아래 근거 줄이나 도표로 내린다.

| Before (Fact) | After (Issue) |
|---|---|
| QSS+, 제안, 노하우는 개별 보상제도를 시행 中 | 현장 직원은 QSS+와 제안 중심으로 개선활동에 참여 中이나, **제도별 보상 체감수준은 낮음** |
| '16년 총 6,167건 中 510건에 대해 총 4억원을 포상 | QSS+ 포상은 **단체포상 중심으로 운영**(510건 中 508건) → 개인 성과보상 곤란 |
| 노하우보다는 특허에 많이 편중 | **노하우 연계 저조** (특허가 많은 것은 문제가 아님) |
| 신규 선발인력이 줄어들고 있음 | 선발 Pool은 감소하는데 **제철소는 現 활동규모 유지를 희망** (모순 상황이 이슈) |
| PSS+ 교육 : 5개 과정 1,940명 교육 | PSS+ 교육 : **문제해결 역량 향상 및 PJT 리더 양성을 위해** 5개 과정/2,312명 교육 (계획대비 146%) |

### 2-2. 헤드라인만 읽어도 전체가 파악되게 쓴다
- "'15년 말부터 선발인원이 급격히 증가"처럼 **궁금증만 유발하고 이유가 없는** 헤드라인은 금지. 원인까지 넣는다. → "'15년 末부터 兩所에서 **경쟁적으로** 선발규모를 확대"
- 앞 장에서 이미 말한 내용("전사기준 수립 후 운영 중이나")은 다음 장 헤드라인에서 반복하지 않는다.
- 처음 읽는 사람이 이해할 수 없는 축약("공장별 과제수행을 위해 선발기준 완화를 요청")은 주체와 목적을 풀어 쓴다.

### 2-3. 대응방안 헤드라인은 앞 장 이슈에 직접 답한다
- 이슈가 "재활동자 선발 기준 완화 요청 + 동일 교육/해외연수 요청"이면 대응방안 헤드라인도 그 두 가지에 대한 입장을 말해야 한다.
- 좋은 예: "현장 고질문제 해결과 혁신역량을 갖춘 인재육성의 당초 취지대로 개선리더를 지속 양성하되, **선발기준을 엄격하게 적용**하고 내실있게 운영하여 직원의 공감대를 유지"

### 2-4. 헤드라인 키워드 = 본문 키워드 = 도형 키워드
- 헤드라인이 "QSS+, 제안, 노하우"인데 본문 도형이 "개선활동, 포상·보상, 지적자산화"를 강조하면 안 된다. **독자의 시선은 텍스트보다 도형에 먼저 간다.**
- 같은 대상을 장마다 다른 용어로 부르지 않는다(재무성과 ↔ 개선성과, 기술성과 ↔ 출원 개인보상). 한 번 정한 용어는 끝까지 쓴다.

### 2-5. 헤드라인 레벨과 형식을 맞춘다
- 같은 레벨의 헤드라인은 같은 형식이다. 앞 헤드라인이 "대외사업 : ~"처럼 **리드 메시지 + 콜론**이면 나머지도 "역량 향상 : ~"처럼 리드 메시지를 붙인다.
- 전체를 아우르는 "성과 및 개선점" 같은 종합 헤드라인은 개별 헤드라인과 레벨이 다르므로 불릿 기호를 다르게 쓴다.

## 3. 본문 논리 원칙

### 3-1. Fact는 보조, Issue가 중심
- "개선리더 양성 누계 5,593명(68%)"은 Fact다. 이슈 박스에 넣지 말고 삭제하거나 도표(Fact 영역)로 옮긴다.
- "포항소/광양소 운영현황" 같은 Fact 도표가 장표의 주인공이 되면 안 된다. 이슈를 받치는 만큼만 쓴다.
- 상단을 "이슈사항"으로 쓰려면 위는 "현황"으로 표기해 둘을 구분한다.

### 3-2. 정의와 이슈를 분리한다
- "QSS+는 설비강건화 활동으로~", "제안은 아이디어 실행에 대한 보상 제도", "IP PJT 기대이익이란~"은 **정의**다. 이슈 문장에 섞지 않는다.
- 개선방안 장에 정의만 쓰고 끝나면 **매뉴얼처럼 무미건조**해진다. 정의는 지우고 "그래서 어떻게 평가·보상하겠다"를 구체화한다.

### 3-3. "왜?"에 위에서 아래로 답한다 (물 흐르듯)
결론 문장 아래에 "왜?"를 두 번 연속으로 답하는 구조로 쓴다.

```
■ 평가는 노력도 위주로 실시되나, 체계적인 재무효과 관리가 미흡하여 개인 보상이 곤란
   - 왜 성과관리가 부족한가? → 활동성과를 재무효과가 아닌 KPI 달성 여부만 확인
   - 왜 KPI만 확인하는가?   → 재무효과가 대부분 기대성과 수준으로 구체성 부족
```
- "성과관리 배점이 20점이라서 미흡"처럼 쓰면 "배점만 올리면 해결되나?"라는 반문을 부른다. 원인은 메커니즘으로 쓴다.
- "~배타적으로 운영되고 있어 → 실제 성과에 상응하는 보상 미흡"처럼 인과가 비약된 연결은 중간 고리를 채운다.

### 3-4. 대립되는 주체의 의견은 분리한다
- 현장(제철소·기술혁신그룹)의 요청과 주관부서(HR혁신실·QSS 섹션)의 검토의견이 한 박스에 섞이면 핵심이 흐려진다.
- `제철소 의견` / `주관부서 의견`으로 박스를 나누고, 같은 이슈끼리 묶어 레벨링한 뒤 중복을 지운다.
- 요청사항을 정확한 말로 옮긴다. "공장당 1팀 의무선발"을 요청한 게 아니라 "선발기준 완화"를 요청했다면 그렇게 쓴다. "선발규모"와 "선발요건"처럼 비슷한 말을 혼동하지 않는다.

### 3-5. One slide, one flow
- 한 장표는 하나의 논점만 다룬다. 특허·노하우 장에서 QSS+·제안을 다시 꺼내면 논점이 흩어진다.
- 헤드라인은 "중복보상 금지로 노하우 연계 불가"인데 맨 아래 줄이 "데이터 공유로 투명한 성과보상 기반 필요"면 흐름이 끊긴다.
- 앞뒤와 무관한 문장("3등급 이상 우수제안 실적은 업적평가 時 참고자료로 제공")은 지운다.
- 스토리 흐름을 끊는 "제도 旣 개선(’16.11.1)" 같은 덧붙임은 지운다.

### 3-6. 프레임을 바꾸지 않는다
- 현황·이슈를 QSS+ / 제안 / 노하우로 썼으면 개선방안도 그 꼭지로 쓴다. 갑자기 제도 / 시스템 / 변화관리로 바꾸면 독자가 앞에서 잡은 틀이 무너진다.

### 3-7. 중복은 무조건 금물
- 요청사항이 현황·이슈와 중복, 개선영역과 개선방안이 중복, 같은 문구(예: "창의 Idea 활동, 전문가 중심, IP PJT 426건")가 1~3줄에 반복되면 읽는 맛이 없고 구두보고 때 말이 꼬인다.
- 같은 이슈(예: 재무형 제안 1.2%)를 상단과 하단에서 두 번 쓰지 않는다. 건수·현황 이슈는 상단에 모은다.
- 이미 운영 중인 제도(예: 현재도 시행 중인 인센티브)를 개선방안으로 쓰지 않는다.
- 상대 조직이 판단할 일정(회장 보고, 마스터플랜 수립)이나 조직도와 같은 협의체 표는 지운다.

### 3-8. 성과 주장에는 근거 수치를 붙인다
- "내용 개편으로 입과자 증가"만 쓰면 설득력이 없다. → "입과자 계획 387명 → 실적 515명 (128명, 33% 增)"
- "성과 – 개선점"으로 쓰면 "성과를 개선하자"로 읽힐 수 있다. **성과 – 반성** 또는 **'17년 반성점 → '18년 중점방향**으로 쓴다.
- "1,940명의 의미는? 수치는 정확한가?"를 스스로 묻는다. 합계·비율·단위를 재계산한다.

### 3-9. 근본적 개선 내용을 쓴다
- "지침화·규정화"는 후속 처리 방법이다. 그 안에 담길 **본질적 개선 내용**(선발기준을 무엇으로 정하는지)을 써야 한다.

### 3-10. 대구(對句)를 정확히 맞춘다
- "현행 – 개선"은 대구가 아니다. **현재 – 향후**, **문제 – 개선**, **'17년 – '18년**, **As-Is – To-Be** 중 하나로 쓴다.

## 4. 문장·표기 원칙 (QSS 보고서 관행)

- **대명사·지시어 금지**: "현장 VOC", "일부 부서", "불만 제기"는 무엇인지 모른다. → "노경협의회 VOC('16.3.12): 개선리더가 현장 문제 해결로 직원을 도와야 하나, 무리한 선발로 오히려 업무 부하 증가", "선발율이 높은 부서(선재 96%, 화성 84%, 제선 77%)의 대근율이 전체 평균을 상회"
- **한 문장 한 목적**: "내실있는 추진을 위하여 … 설비고도화에 기여하고자 함"처럼 목적이 두 개면 무엇을 하자는 건지 흐려진다. → "목적 : '18.上 충실도 진단결과 광양소 대비 수준 열위 → My M&S 활동 在진단을 통해 개선방향 도출"
- **종결 패턴 통일**: 보고서 전체가 명사형(~확대, ~필요, ~有)이면 "~하고 있음"을 섞지 않는다.
- **출처를 붙인다**: 경영층 발언은 `" … " (제철소장 QSS 멘토링 時)`, `(’17.1.17 본부장 회의)`처럼 화자와 시점을 쓴다. 통계에는 `* 출처 : ’19.上 광양소 유지관리 진단 결과`처럼 기준을 단다. 출처 칸을 비워 두거나 "000개소"로 남기지 않는다.
- **QSS 보고서 한자·약어 관행**(보고서 안에서 일관되게): 中, 後, 時, 內, 外, 旣, 無, 有, 多, 低, 高, 要, 可, 難, 弱, 强, 增, 末, 上/下, 兩所, 浦/光, 現, 新, 全, 型, 化, 案. 연도는 `’18년`, 기간은 `’18.4~’19.12`, 반기는 `’19.上`.
- **숫자 표기**: "컨설턴트 9명, 1,920日"보다 "컨설턴트 9명 / 1,902日"처럼 구분해 한눈에 읽히게 한다. 같은 반복 수식어("’16년"을 박스마다 반복)는 제목으로 올린다(“활동현황(’16년)”).
- **불필요한 번호·기호 삭제**: "1 단기 : / 2 장기 :" → 박스 안에 "단기", "장기"만. "2018년" → "’18년".
- **용어 정합성**: 포상(단체·훈격)과 보상(개인·금전), 실행노력과 성과창출처럼 독자가 차이를 물을 만한 말은 정의하거나 하나로 통일한다.
- **수식 형태 지양**: "수주전 기여도/수주액, 수주후 기대이익/투입자원"처럼 공식으로 쓰면 복잡하다. "수주 前은 기여도로 사장표창, 수주 後는 실현이익으로 특별보상"처럼 핵심 개념이 드러나게 쓴다.
- 3줄짜리 이슈 문장은 2줄로, 2줄로 꺾인 문장은 가능하면 1줄로 편다.

## 5. 불릿·레벨링 원칙

- **불릿 체계 예시**: `■ 헤드라인(주장) → ▷ 근거·부연 → - 세부 → * 각주`. `※`는 **참고**라는 뜻이므로 일정계획처럼 중요한 내용에 쓰지 않는다. `☞`는 결론·시사점에만.
- **상하 레벨은 포함 관계**일 때만 쓴다. "성찰활동 정례화로 ~" 아래에 동등한 내용을 하위로 달면 레벨링 오류다. 한 문장으로 합치거나 같은 레벨 불릿 두 개로 쓴다.
- **대상과 활동을 같은 불릿에 나란히 두지 않는다.** "포스코 IP PJT 수행 지도(4명)" 아래 "(광) 하역~고로 물류 동기화(7건)"와 "데이터 분석으로 원인·개선안 도출 지원"을 같은 레벨로 두면 오류다. → 한 문장: "광양제철소 하역~고로 물류 동기화 등 포스코 PJT 7건의 데이터 분석, 문제 원인 및 개선안 도출 지원"
- **서브 불릿 개수 패턴 통일**: 어떤 항목은 서브 0개, 어떤 항목은 2개면 혼란스럽다.
- **상위 문장이 하위를 포괄해야 한다.** 하위 내용(대내 찾아가는 교육, 대외 상생 컨설팅)을 포괄하지 못하는 상위 문장은 지우고 하위를 "대내 / 대외"로 정리한다.
- **'○' 불릿이 왼쪽에 몰려 오른쪽이 비면** 왼쪽에 카테고리 박스(예: `全 직원 Mind set 교육 | GB/BB/MBB 과정 보완 | 전문가 육성 확대`)를 세우고 오른쪽에 내용을 둔다(카테고라이징).
- 박스 안 문장 패턴(대상/내용, 목적/기본방향, 현행/개선)이 박스마다 다르면 산만하다. 한 장표 안에서는 하나의 패턴으로 쓴다.
- **동일 패턴 유지**: 꼭지마다 "현황 → 이슈"면 전 꼭지가 같은 순서여야 한다("이슈 → VOC", "이슈 → 이슈"를 섞지 않는다).

## 6. 시각화·레이아웃 원칙

- **좌우 균형**: 도표가 전달하는 메시지에 비해 면적이 크거나, 좌측은 가볍고 우측은 무거우면 불안해 보인다. 좌우 도형 크기를 맞춘다.
- **색은 의미가 있을 때만**: 특정 대상(광양)을 붉은색으로 칠하면 의도치 않게 강조된다. 같은 레벨 박스(선발요건/선발규모/교육체계)는 같은 색. **그라데이션은 순서를 표현할 때만** 쓴다.
- **강조점은 키워드에**: 볼드·컬러는 문장의 핵심어(예: "시그마로 內 재무효과 등록 및 검증 기능 개발")에 주고, 수식어에 주지 않는다. 개선방향처럼 결론이 되는 부분은 폰트 크기·색·굵기로 부각하고, 현상·원인은 작은 폰트 한 줄로 앞에 둔다.
  - 예: `교원은 자신이 확보한 연구비로 연구계약직 활용 인원을 결정하려는 의식 强 ← 연구·구매 행정의 복잡성에 기인` (작게) → `"연구행정과 구매행정의 간소화 선행 後 교원의 Lab 비서 감축 설득 필요!"` (크게)
- **그래프 품질**: 꺾은선이 매끄럽게 이어지는지, 전후 비교 기준선(예: "선발기준 개선")이 눈에 띄는지, 0명 같은 불필요 라벨로 복잡해지지 않는지 본다. 도표 제목에 밑줄 금지, 제목 안 중복어("차수당 평균") 제거, 단위 표기(`단위 : 명`) 필수.
- **도표 제목에 메시지를 넣는다**: "포항소 운영현황" → "포항소 : 차수당 145명 → 126명".
- **흐름을 도형 방향으로**: 좌→우로 흐르는 내용에 가운데 세로선을 쓰지 말고 오른쪽을 향하는 화살표 도형을 쓴다. 내용 흐름과 맞지 않는 화살표·삼각형(엉뚱한 인과로 읽힘)은 지운다.
- **업무 순서대로 배열**: 2×2 배열은 읽는 순서가 없다. "Idea 발굴·심의 → PJT 수행 지도 → 성과 검증" 순서로 위에서 아래로 놓고, 성격이 다른 것(그룹사 지원)은 따로 둔다.
- **비교는 가운데 축**: 현재/향후 비교표는 비교 항목(실습주제·산출물·진행방식)을 가운데 열에 두고 좌우에 '17년 / '18년을 배치한다. 현행·개선 박스 크기를 같게 한다.
- **표 안에 다른 카테고리를 섞지 않는다**: 학습목표·Keyword·시점 표에 "진행(1~2Hr)"이 끼면 표 아래 `▷`로 뺀다.
- **불필요한 선·분리 합계 제거**: 박스 안 선이 많거나 합계가 따로 떨어져 있으면 복잡하다. 이미 전체를 S/A/B로 나눴다면 부분집합(스마트형 41건)을 다시 S/A/B로 나눌 필요 없다.
- **번호 일치**: 도형 번호와 설명 번호를 맞춘다.
- **중요도 순 배치**: 키워드 중요도가 중복금지 > 심사부담감이면 위에서부터 그 순서로 놓고, 원인–결과 쌍(심사부담감 → 일반제안 선호, 중복금지 → 우수제안 회피)을 선으로 연결한다.
- **대비 구조로 가독성**: 수주 前 / 수주 後, As-Is / To-Be는 좌우 대비로 놓는다.

## 7. 교정 체크리스트 (셀프 리뷰용)

**구성**
- [ ] 목차 꼭지가 현황·이슈 → 대응/개선방안 → 향후계획까지 같은 프레임, 같은 순서인가
- [ ] 장별 분량 균형이 맞는가 (이슈 3장 vs 방안 1장 아닌가)
- [ ] 향후계획을 별도 장으로 두고 PDCA·모니터링까지 구체화했는가
- [ ] 지면 채우기용 다짐·VOC·조직도가 없는가

**헤드라인**
- [ ] 헤드라인이 Fact(~시행 中, 총 n건 n억원)가 아니라 Issue/의견인가
- [ ] 헤드라인만 이어 읽어도 보고 전체가 이해되는가
- [ ] 궁금증만 유발하지 않고 원인까지 담았는가
- [ ] 대응방안 헤드라인이 앞 장 이슈에 직접 답하는가
- [ ] 헤드라인·본문·도형의 키워드가 일치하는가
- [ ] 같은 레벨 헤드라인의 형식(리드 메시지 + 콜론 등)이 같은가

**논리**
- [ ] Fact는 근거로만 쓰고, 정의는 이슈와 분리했는가
- [ ] "왜?"에 두 단계로 답해 위→아래로 흐르는가
- [ ] 현장 요청과 주관부서 의견을 분리했는가, 요청을 정확한 말로 옮겼는가
- [ ] 장표마다 논점이 하나인가 (One slide, one flow)
- [ ] 중복 문장·중복 이슈·이미 시행 중인 제도가 없는가
- [ ] 성과 주장에 수치 근거(계획 → 실적, 증감률)가 있는가, 수치를 재계산했는가
- [ ] 지침화 같은 형식 대신 본질적 개선 내용을 썼는가

**문장·표기**
- [ ] "현장 VOC", "일부 부서" 같은 지시어를 구체화했는가
- [ ] 한 문장에 목적이 하나인가
- [ ] 종결 패턴이 통일됐는가
- [ ] 경영층 발언·통계에 출처(화자, 시점, 기준)가 있는가, "000" 자리표시가 남아 있지 않은가
- [ ] 같은 대상을 같은 용어로 불렀는가
- [ ] 대구가 맞는가 (현재–향후, 문제–개선, As-Is–To-Be)

**불릿·시각화**
- [ ] 불릿 기호의 의미(■, ▷, -, *, ※, ☞)를 지켰는가, 중요한 내용에 ※를 쓰지 않았는가
- [ ] 상하 레벨이 포함 관계인가, 서브 불릿 개수 패턴이 일정한가
- [ ] 좌우 균형, 같은 레벨 같은 색, 그라데이션은 순서에만 썼는가
- [ ] 도표 제목에 메시지·단위가 있고, 기준선·라벨이 깔끔한가
- [ ] 도형 방향·배열이 읽는 순서·업무 순서와 맞는가

## 8. QSS 내용 작성 가이드

### 8-1. 자주 쓰는 QSS 개념 (용어를 정확히)
- **활동 구분**: 일상개선활동(5S·마이머신·My M&S) / 과제활동(개선리더과제·일상과제) / 특별활동(모델 Plant·혁신공장만들기) / 솔선·격려(임원·부장 소통) / 인재양성(개선리더·FT).
- **유지관리 단계**: 3정 5S(발생원 제거) → 기능복원(열화부품) → 성능복원(도입시 성능) → 성능향상. 혁신공장만들기는 발생원 제거·설비강건화, 공장장 모델 Plant는 열화방지·설비고도화.
- **유지관리 Process**: 전문가 진단(분기 1회) → 회귀여부 판정 → (회귀 時) 6개월 內 재활동 → 완료 인증.
- **My M&S 진단 5단계**: 활동계획서(KPI 연계 목표) → 점검시트(측정점검 설계) → 불합리 발굴(眞因 추적) → 개선실행(근본원인 개선) → 유지관리(KPI 효과 산출, 위험성평가·작업표준 변경관리).
- **성과 구분**: 기대이익과 實재무성과(재무검증 기준 적용)를 구분해 쓴다. 현업과 중복되는 원가절감, 증산 수익, 기회비용은 재무성과에서 빠질 수 있으니 산정 기준을 명시한다.

### 8-2. QSS 보고서에서 설득력이 생기는 장치
- **경영층 지시·VOC로 배경 열기**: CEO 지시, 제철소장 멘토링 발언, 노경협의회 VOC를 따옴표 + 출처로 배경 맨 앞에 둔다. 그 바로 아래에 이를 뒷받침하는 데이터를 둔다.
- **As-Is / To-Be 관점 전환**: "단기적 조치(도색·교체 → 재발생 악순환, 주기적 진단 必要)" vs "발생원 제거(근본원인 제거 → 추가 노력 없이 유지 可)". 각 칸에 정의 한 줄 + 결과(☞) 한 줄.
- **원인 – 결과 – 개선방향 3단 표**: 개선활동 / 인력운영처럼 축을 나눠 원인(단순 도색·교체, 주 52시간), 결과(회귀, 활동 難), 개선방향(발생원 제거 중심 3정 5S, 주임단위 발굴 + TF 개선)을 정렬한다.
- **업종 비교로 방향 정당화**: 조립산업(TOYOTA, 작업방법 개선) vs 장치산업(제철소, 설비 개선).
- **진단의 한계도 적는다**: "유지관리 진단의 관대화를 고려하면 재활동 개소가 추가로 있을 수 있음 → 혁신 피로도·신뢰성 하락 유발 可"처럼 숫자의 한계를 밝히면 신뢰가 오른다.
- **절차는 번호 흐름으로**: ① 대상공장 선정 → ② 활동방향 수립 → ③ 과제도출 → ④ Kick-Off → ⑤ 개선활동. 각 단계에 기준·주체·주기·참석자·완료 판정 기준(예: 불합리 재발생 없이 6개월 유지 → 완료 판정, 우수결과 포상 상신)을 적는다.
- **역할 분담 명시**: 주임단위 → 불합리 발굴·등록 / 개선지원 TF(설비관리반 內 조업·정비 + 개선리더) → 발생원 제거·유지관리.
- **실적 보고에는 성과와 반성을 짝으로**: 성과마다 ▷로 수치 근거를 달고, 반성은 다음 해 중점방향과 1:1로 연결한다.

### 8-3. 첨부: 발생원 분석 양식 작성법
```
[첨부 n] ○○ 없는 △△ 만들기          ← 제목은 '없애려는 현상 + 대상 설비'
공장명 | 공정명 | 공장장 | 담당 FT
활동 방향 : ○○ 공정 중 △△ 발생 방지
발생원        : 근본 발생 메커니즘 (물리·화학적 원인)
공정별 상세 발생원 : 공정 흐름(※ A → B → C) 순서대로 설비별 발생 지점과 원인
발생원 제거 방향  : 상세 발생원과 1:1로 대응하는 제거·차단·최소화 방향
                  ★ 접근 방향 / ※ 착안사항 / 예) 아이디어
기대효과(있으면) : 절전, 재사용 비용 절감 등
```
- 상세 발생원과 제거 방향의 항목 수·순서를 맞춘다.
- 품질 영향이 없어 검토에서 빼는 항목은 "→ 검토 제외"로 이유와 함께 밝힌다.
- 오탈자(Sclae, Scuruber, Woring 등) 확인.

## 9. 교정 결과 출력 형식

교정을 요청받으면 장표마다 아래 형식으로 답한다.

```
### 슬라이드 n : (장표 제목)
**교정의견**
1. (위치) "원문 인용" → 문제 유형(헤드라인 Fact/지시어/레벨링 오류/중복/균형 등)
   → 왜 문제인지 한 줄
   → 수정 방향
2. ...

**After**
(수정한 헤드라인과 본문. 장표 구조가 바뀌면 박스·도형 배치를 텍스트로 표시)
```
마지막에 보고서 전체에 걸친 공통 지적(프레임, 분량 균형, 용어 통일)을 3줄 이내로 요약한다.
