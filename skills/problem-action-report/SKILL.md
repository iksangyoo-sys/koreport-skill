# 문제해결·추진방안 보고서 작성·교정 Skill

현업에서 가장 많이 쓰는 **문제해결형 보고서**와 **추진방안(기획형) 보고서**를 쓰거나 교정할 때 쓰는 통합 스킬이다.

**핵심 한 줄: 배경(왜) → 현황·문제·원인(질문) → 방향(관점) → 대책·추진내용(답) → 실행계획이 꼬리에 꼬리를 물고, 질문과 답이 1:1로 맞아야 한다.**

## 목적과 적용 범위

- **용도**: 정책·업무 개선방안, 문제해결 대책, 제도 정비방안, 사업 활성화방안, 운영체계 개선방안, 추진방안, 교육지원방안, 관리계획.
- **비대상**: 단순 정보 공유·회의록·실적 집계만 요구하는 문서. 이런 경우 사용자의 형식을 우선한다.
- **일반 방법론과의 관계**: 독자 니즈, 메시지 도출, 묶고–풀기 일반, 문장 교정 일반, 1-page 양식, 시각화 일반은 `koreport-skill`을 따른다. 이 스킬은 그 위에 **문제해결·추진방안 보고에 특화된 것**만 얹는다.
- **출처**
  - 문제해결형: 사용자 첨부 '보고서 코멘트' 8건(1649, 1650, 1656, 1659, 1662, 1666, 1669, 1677). 예시는 이들 자료의 *교정 방향*을 요약한 것이며 실증 자료나 확정된 정책 판단을 뜻하지 않는다. 원본은 HWP 본문을 추출해 다시 PDF로 만든 사본이라 표 배치·글꼴·강조가 달라질 수 있으므로 내용 중심으로 활용한다.
  - 추진방안형: 교안 [부록3] 「추진방안 보고서 Case study」
    - Case A: 개인정보보호 교육 및 관리계획 (Raw 자료 → 초안 → 수정의견 → 최종)
    - Case B: 이차전지소재 밸류체인 교육지원 방안 (I. 검토배경 → II. 현황 및 이슈 → III. 추진방향 → IV. 추진내용, 장마다 Before → 교정의견 → After)

## 절대 규칙

1. **제공 자료 우선**: 사용자 문서에 있는 사실과 요구사항을 먼저 확인한다. 근거가 없는 수치, 법률, 통계, 사례, 인용, 일정, 예산, 원인을 만들지 않는다. 비어 있는 곳은 `[근거 확인 필요]`, `[결정 필요]`, `[ ]`로 남긴다.
2. **사실·판단·가설 분리**: 현황은 근거가 있는 사실로 쓴다. 추론은 '추정/검증 필요'로 표시하고, 근거 없는 인과관계를 확정적으로 쓰지 않는다.
3. **문제와 원인을 구분**: '실적 부진'은 문제, '지원절차 복잡'은 검증해야 할 원인일 수 있다. 대책을 먼저 떠올렸다고 원인이 사실로 확인된 것은 아니다.
4. **질문과 답을 1:1로 맞춤**: 해결방안·추진내용은 실태분석·이슈에서 확인한 원인을 겨냥한다. 앞에서 중요하게 다룬 이슈를 뒤에서 떼먹으면 안 되고, 반대도 안 된다. 동문서답이면 질문이든 답이든 **무조건 맞춘다.**
5. **표현을 정확하게**: 제목은 대상과 조치 방향을 한 줄로. 명칭, 주어·서술어, 목적어·동사, 병렬구조, 수치의 단위와 시점을 검증한다.
6. **사용자 승인 게이트**: 사용자가 단계별 승인 방식을 요청한 경우 각 단계 결과를 보고하고 승인을 받은 후 다음 단계로 간다. 그렇지 않으면 전체 작성·교정을 수행한다.
7. **정보 보호**: 원본의 개인정보·비공개 회사 정보를 결과물에 불필요하게 재노출하지 않는다.

## 0. 작업 순서와 보고 유형 선택

1. **입력 자료와 요구 확인**: 보고 주제, 수신자(경영층·직책자)와 그 관심·지시사항, 의사결정 필요 사항, 근거 자료, 분량·형식. 부족하면 질문하거나 가정을 밝히고 '미확인 사항'으로 표시한다. 교정 요청이면 **원문 유지본**과 **수정안**을 구별한다.
2. **보고 성격 확인**: 의사결정을 받을 보고면 **검토배경**, 이미 결정된 일의 후속이면 **추진배경**.
3. **유형 선택**

| 구분 | 문제해결형 | 추진방안형(기획형) |
|---|---|---|
| 언제 | 문제·원인이 핵심이고 대책을 제시 | 새 일을 기획하거나 여러 부서 내용을 묶어 방향과 실행안을 제시 |
| 표준 흐름 | 검토배경(Why 1) → 실태분석(Why 2: 현황·문제·원인) → 해결방안(How) → 세부 추진계획(What) | 검토배경 → 현황 및 이슈 → 추진방향 → 추진내용 → 액션플랜 |
| 무게중심 | 원인 분석과 원인–대책 대응 | 검토배경과 추진방향(경영층이 가장 관심) |

   두 유형은 섞어 쓸 수 있다. 예: 문제해결형에 '추진방향' 장을 넣거나, 추진방안형의 '현황 및 이슈'를 현황·문제점·원인으로 쪼갠다.
4. **흐름 구분 (1장)** → **제목 (2장)** → **장별 작성 (3~7장)**: 앞뒤를 오가며 아귀를 맞춘다(Iteration).
5. **본문 전개 (8장)**: 장표 하나하나는 結·根·方·課로.
6. **문장 교정 (9장)** → **정합성 점검 (10장)**.

## 1. 흐름 구분

**배경 → 현황 → 문제점 → 원인 → 개선안**을 기본으로 하되, 보고 목적에 맞게 자유롭게 조합한다.

- 조합 예: ① 현실태(현황·문제점·원인) → 개선방안 ② 현황 → 문제점 및 원인 → 개선방안 ③ 검토배경 → 현실태 → 개선방안

| Step | 할 일 | 요령 |
|---|---|---|
| 1. 흐름 구분 | 자료를 유사성·연관성·특징으로 덩어리 짓기 | 덩어리마다 대표 키워드로 네이밍 → 유사 콘텐츠 통합, 중복 제거, 계층화하여 흐름에 맞게 재배열 |
| 2. 현황 정리 | 독자(직책자)가 알아야 할·관심 있는 사실·데이터 요약 | 백화점식 나열 금지. 메시지(이슈·방안) 깜이 되는 주제의 디테일만 |
| 3. 이슈 정리 | Facts & Data 분석으로 발견·유추한 문제점, 분석 결과, 원인 | 내용이 많으면 현황·문제점·원인 분리. 단순하면 한 문장에 녹이되 문장 패턴 통일 |
| 4. 개선방안 | 원인 해결·조치 방안 구체화, 또는 향후 추진 일정·순서 | 필요하면 도표·도형으로 가독성 향상 |

### 표준 목차 — 문제해결형

```text
[대상] [개선/해결/체계화/활성화] 방안
1. 검토배경
   □ 중요성: 왜 중요한가?
   □ 시급성: 왜 지금인가?
2. 실태분석
   □ 현황 및 문제점
      ○ 주요 현황·추세(근거/기준시점)
      ○ 목표·수요와 실제 성과의 차이(핵심 문제)
   □ [핵심 문제]의 원인
      ○ 원인 A(검증 근거)
      ○ 원인 B(검증 근거)
      ○ 원인 C(검증 근거)
3. [문제] 해결방안
   □ 원인 A에 대한 조치
   □ 원인 B에 대한 조치
   □ 원인 C에 대한 조치
4. 세부 추진계획
   □ 추진체계
   □ 추진전략(입법/예산/소통 등 필요한 항목)
   □ 추진일정 및 점검 지표
```

### 표준 목차 — 추진방안형

```text
[대상] 추진방안 / 지원방안
I. 검토배경 (중요성 2줄 + 시급성 2줄)
II. 현황 및 이슈 (니즈 → 그러나 장애 → 이에 지원 필요) + Take away
III. 추진방향 (헤드라인 키워드 + 대상별 서브라인)
IV. 추진내용 (추진방향과 같은 순서·같은 행)
V. 액션플랜 (추진체계·일정)
```

### Case A 교훈 (개인정보보호 교육·관리계획)

- **장 제목이 내용과 맞는가?** '추진배경'에 목적·현실태·문제점·개선방안이 섞이면 이슈와 방안이 안 보인다. → '현실태(현황 및 문제점)'로 바꿔 **왜 필요한지(중요성·시급성)**를 보인다.
  - 현황: 유출사고 빈발을 수치·사례로 보이고, 근거는 `*` 각주로. (예: *'12.11 ㅇㅇ실 정보유출, ㅇㅇ협력사 정보유출 등)
  - 원인: "사내 지침*은 있으나, 직원들의 인식 부족 및 관리 체계 미흡에 기인"처럼 근본 원인까지 내려간다.
- **개선안은 원인마다 1덩어리**: 이슈가 '교육 부족'과 '협력사 관리 미흡' 둘이면 개선방안도 '교육강화'와 '협력사 관리' 둘. 덩어리마다 `대상 / 방법`을 단다. '교육일정 및 방법'만 쓰고 협력사 관리를 떼먹으면 안 된다.
- **같은 대상은 한 용어로**: 내부/외부, 아진산업/협력사, 내부/협력사를 혼용하지 말고 하나만. 문장 패턴도 맞춘다('취급·관리 업무를 수행하는 직원' vs '취급 담당직원' → '취급 직원'으로 통일).
- **일정은 구체적으로**: '매 분기 마지막 달' → '3, 6, 9, 12월', '매 반기 마지막 달' → '6, 12월'.
- **선택인지 병행인지 명확히**: '집합교육, 이러닝' → '집합교육, 이러닝 병행'.
- **당연한 말·의미 중복 삭제**: '교육실시 전 ~ 조정'의 '교육실시 전', '발생 시 별도 교육'의 '별도'.
- 주술관계: '목적외 이용·제공 ~ 등을 정기적으로 관리' → '목적외 이용·제공 **사례** 등을 정기 관리'.

## 2. 제목 검증

- '대상 + 달성하려는 방향 + 방안/대책' 형태를 기본으로 한다.
- 필요 이상의 병렬 제목, 의미가 겹치는 구절, 목적과 어울리지 않는 동사를 고친다.
  - '빈집 관리 활성화 방안' → '빈집 관리 체계화 방안'(1656)
  - '햇빛소득마을 활성화 및 제도 개선방안' → '햇빛소득마을 활성화 방안'(1677; 제도 개선은 활성화 수단에 포함)
  - '식품사막화에 따른 식품접근성 약화 대책' → '인구감소지역 식품접근성 제고 대책'(1659)
- **장 제목**도 내용과 맞춘다(추진배경 vs 검토배경 vs 현실태). 하위 꼭지에 상위 장 제목과 같은 말을 쓰지 않는다.

## 3. 검토배경 (Why 1) : 중요성과 시급성을 세운다

- 배경·상황·목적을 세분해 나열하기보다 **중요성**과 **시급성**이 명료하게 드러나도록 정리한다(1650).
- **중요성은 논리의 강도, 시급성은 논리의 전달 속도**다. 둘 다 있어야 독자와 강하고 빠르게 공감대가 생긴다.
- **중요성 (왜 중요한가)**: 독자가 익히 아는 사업 전망은 '뉴스'가 못 된다. 1줄로 터치만 하고 **첫 헤드라인부터 독자 관심사(보고 주제)로 바로 들어간다.** 주제를 분산하지 말고 한 방향으로 몰아간다(우리 강점 → 그것을 움직일 동력이 경쟁력의 핵심 요인).
- **시급성 (왜 지금인가)**: 경쟁사·정부 등 **외부가 이미 움직이고 있다**는 논리가 경영층에 부담을 주지 않으면서 가장 설득력이 크다. 내부 논리(신증설·신규채용 급증)는 좋지만 뒤의 현황과 겹치면 빼고 외부 논리만 남긴다.
- **검토배경의 핵심 주장은 실태분석·현황에서 실제 근거로 확인되어야 한다.**
- **스토리 무리수 점검**: '양적 성장 → 질적 성장'처럼 현실 단계(아직 가동 준비 단계)와 맞지 않거나 보고 범위 전체를 커버하지 못하는 논리는 버린다.
- **헤드라인만 모아 한 줄로 읽는다.** 섬처럼 끊기면 다시 짠다.
  - Before 흐름: "밸류체인 경쟁력 강화 필요 → 생산품질 최적화로 질적 성장 요구 → 직원역량 강화 지원방안 필요" (서로 연결 안 됨)
  - After 흐름 (4줄 = 중요성 2줄 + 시급성 2줄):
    1. 미래 먹거리 이차전지소재, 원료에서 소재·리사이클링까지 'Full 밸류체인'을 완성
    2. 한발 앞서 10년간 준비해온 밸류체인, 추진 동력이 될 전문인력 양성이 경쟁력의 핵심 요인
    3. LG엔솔, SK온 등 배터리 제조사도 자체 「배터리 아카데미」를 개설, 교육 시작
    4. 우리도 글로벌 Top-tier로의 성장을 이끌 인재육성에 박차를 가할 시점
- 근거 배치: 수치는 `*` 각주, 경영층 발언은 "인용"(출처·일자), 타사 사례는 하단 비교 박스로. 자료에 없는 수치·인용·타사 사례는 지어내지 않고 `[ ]`로 비운다.

## 4. 실태분석 / 현황 및 이슈 (Why 2)

### 4-1. 현황 및 문제점

- 현황은 **보고 제목의 대상, 독자 관심·지시사항과 직접 연결된 데이터**로만 쓴다. 규모, 운영 현황, 공급·수요, 성과, 제도, 추이를 먼저 제시한다. 대상과 동떨어진 현황을 늘어놓지 않는다(1666). 핵심과 무관한 분석을 확대하지 않는다(1659).
- 가능하면 목표 대비 실적, **수요 대비 공급**(1666), 기간별 변화, 지역·대상별 차이를 함께 점검한다.
- 현황 다음에 **원하는 상태와 실제 상태의 차이**를 문제로 명시한다. 정량·정성 성과로 문제를 정의한다('사업부진'이 무엇인지, 1677).
- '[지속 증가]', '[대부분]', '[급증]'처럼 확인 가능한 주장은 출처·기준시점·통계를 붙인다. 근거가 없으면 표현을 제한하고 `[근거 확인 필요]`를 표시한다(1649).
- 현황과 '기존 정책 한계' 같은 분석 항목은 역할을 구분해 중복시키지 않는다(1662).

### 4-2. 원인 분석

- '무엇의 원인인가?'를 명시한다. 예: '사업부진 원인', '서비스 공백 원인'.
- 법·제도, 운영체계, 인프라, 재원, 이해관계, 인식 등 **상호 중복이 적고 주제에 맞는** 범주로 분류한다(1649).
- 현상·영향·원인을 다른 층위로 분리한다. 예: '법적 근거 미비'는 현황의 피해가 아니라 그 피해를 설명하는 원인 후보다(1656). 규제가 필요한 **근본원인**을 분명히 한다(1669).
- 원인과 근거의 연결이 부족하면 '확인 필요'로 둔다.

### 4-3. 이슈 스토리 (추진방안형)

- **현황 및 이슈는 '질문'이다.** "현재 이런 모습이고 저런 문제가 드러났다, 어떻게 할까?" 뒤의 추진방향·추진내용이 **답**이다.
  - 예: 이슈는 '기본교육 참여율 저조'인데 추진내용은 '직책자 조직 안정화 역량 강화' → 이슈를 "공정 가동·안정화, 다양한 구성원 화합 등이 시급한 현안 → 리더십·조직역량 컨텐츠 확대 의견 多"로 바꿔 답과 맞춤.
- 3단 흐름 예: **니즈 → 그러나 장애 → 이에 지원 필요**
  - 소재사의 공장 신·증설 및 신규채용 급증으로, 생산 안정화를 위한 직무역량 확보 니즈가 높다.
  - 그러나 새로운 공장 가동에 바쁜 소재사들은 자체 교육체계 구축, 과정 개발 및 운영이 어려운 상황이다.
  - 이에, 밸류체인 全 소재사의 역량이 동등한 수준으로 향상되도록 인창원의 지원이 필요하다.
- **Take away(하단 결론 박스)는 다음 장(추진방향·해결방안)으로 넘기는 커넥터**다. 첫 헤드라인과 의미가 겹치는 말은 빼고, '방향을 암시하는 워딩 + 지원'을 엮는다.
- **'36도까지 올라가서 덥다'식 문장 금지**: "학습여건 불비로 교육을 충분히 못함"은 원인처럼 보이지만 의미 중복이다. '학습여건'을 잘게 쪼개 묘사하고 '불비'의 원인을 밝힌다.

### 4-4. 현황 문장을 이슈로 바꾸기

| 문제 | Before | After |
|---|---|---|
| 현황만 있음 → 이유·비교를 붙인다 | E직군 채용이 대폭 증가했으나, 도입교육 과정 입과 없이 채용 후 바로 현업 배치 | 소재사 E직군 도입교육 과정이 없어* → 채용 즉시 현업에 배치하여 OJT 훈련 (*P직군은 그룹입문교육(3주)에 입과) |

| 의미 중복 결과 | 교육체계·교재가 준비되어 있지 않아 체계적 교육과정 편성 불가 | 직무별 필수·선택 교과목이나 난이도 구분 없이 → 부서 內 작업·기술표준서, 업무매뉴얼 파일로 학습 ("그럼 지금은 어떻게 배우나?"에 답) |

| 대충 뭉갬 ('회사별로', '규모 구성') | 회사별로 소규모 인원으로 집합교육 학습자 규모 구성이 쉽지 않음 | 퓨처엠, SNNC 外 소재사는 인원규모가 작아, 직무별·계층별 10명 이상의 집합교육 구성이 곤란 |

### 4-5. 가독성

- **헤드라인 키워드(독자 관심·지시사항)를 가장 도드라지게.** 키워드의 데이터는 매우 구체적으로, 가능하면 그래프로.
- **키워드를 직접 받치지 않는 근거는 톤다운**한다. Case B: 공정안정화 근거 4개(가동준비 단계, 사업장 전국 분산, 신규채용 비율, 이직률) 중 직접 받치는 것은 가동준비·신규채용 2개뿐. '사업장 지도' 그림은 시선을 뺏으므로 빼고 '※ 사업장이 광양, 포항, 세종, 구미 등 전국에 산재' 1줄로. 이직률은 신규채용과 겹치므로(MECE 아님) 참고 1줄로.
- 수치 키워드는 그래프로. 항목명이 길면 **가로막대**.
- 본문 도표는 **항목 3~4개**. 상징성 낮은 항목은 뺀다. 행·열은 하나 빠지면 표현이 안 되고 하나 더 있으면 거추장스러운 수준으로. 선은 꼭 필요한 곳에만, 색도 최소로.
- **'1131' 단락 패턴**: 헤드라인 1줄 + 서브헤드라인 1줄 + 본문 3~4줄(박싱) + 부연·참고 1줄 = 6~7줄. 장표를 상·하 1:1로 나눠 각 단을 1131로 쓰면 장표당 13줄 내외. 헤드라인 밑 본문 전체를 통째로 박싱하지 않는다.
- **Level이 다른 카테고리를 나란히 두지 않는다.** '기본과정·직무과정'(교육과정의 하위)과 '교육운영'은 Level이 다르다. **Color bath effect**(같은 Level은 같은 색)로 차이를 표현한다.

## 5. 추진방향 : 한 장에 무엇을 어느 쪽으로 할지 보인다

추진방안형에서 필수, 문제해결형에서도 대책이 여러 갈래면 넣는다. "그래서 무엇을 어떤 쪽으로 추진하겠다는 건가?"에 답하는 장표다. 여기가 확실히 어필되면 뒤의 추진내용은 90% 먹고 들어간다.

### 5-1. 헤드라인

- **현황 및 이슈의 Take away에 답한다.** 대화처럼 이어지게.
  - Take away) 밸류체인 경쟁력 확보를 위해, 全 소재사의 역량이 동등한 수준으로 향상되도록 종합지원이 필요!
  - 추진방향) 밸류체인 內 인재양성 사각지대가 없도록 **촘촘히** 교육과정을 구성하고, **두텁게** 지원
- **추진내용 전체를 관통하는 워딩**, 보고서를 덮었을 때 뇌리에 남을 키워드를 박는다. 한자보다 **순 우리말**이 강력하다. 형용사·부사를 쓰되 실체를 각주로 풀어준다.
  - `* 촘촘히 : 全 소재사에 동등한 수준의 교육을 빠짐없이 제공 | 두텁게 : 교육체계 구축부터 과정운영까지 Shared service`
- 키워드 채집법: Before 문장의 키워드를 **5W2H로 파고 내려간다.**
  - Before) 밸류체인을 하나의 종합회사로 인식하고 전체 경쟁력 강화를 위한 교육체계 구축 및 운영지원 (틀린 말 없으나 뇌리에 남을 워딩이 없음)

### 5-2. 서브라인

- 헤드라인이 관점·개념(What)이면, 서브라인은 **What의 대상을 나누고 대상별 How를 부사로**. 헤드라인과 겹치면 안 된다.
  - Before) 그룹 공통 과정은 소재사에도 동일 수준 제공 | 직무에 필요한 과목은 아카데미 운영 | 현장 실무교육은 회사별 자체교육 지원
  - After) ☞ 그룹공통 과정은 **똑같이**, 밸류체인 직무과목은 **모두 함께**, 현장 실무교육은 회사별로 **따로**

### 5-3. 관점·색·배치

- **I 관점 → YOU 관점**: 작성 부서의 운영 용어(기본과정·직무과정·특화과정)를 독자의 역량 이름으로 바꾼다. I 관점이면 **빠지는 영역**(현장 OJT, 사외교육, 자기학습)이 생기므로 `[보완 필요]`로 표시한다.
  - YOU 관점 예: 리더십/조직역량(신입·경력·직책자) – 안전/개선역량(안전, QSS) – 직무 전문(아카데미) – 기반 직무기술(기술교육, 디지털) – 현장 실무(OJT, 자기학습, 사외교육)
- **색은 의미를 줄 때만**: 같은 범주 1색, 엷은 색 Low·짙은 색 High, 부각 대상만 팝업. 한 섹터에 3색 이상이면 색마다 의미를 텍스트로 기입. 의미 없는 6색 떡칠은 독이다.
- **연결 대상은 바싹 붙인다.** 추진방향과 추진내용이 **'一'자로 한 줄에 읽히게** 배치한다(방향 번호 행 = 내용 번호 행).
- 장 하단 Take away로 기대효과를 한 줄 맺는다. (예: "소재 전문 지식과 실무를 겸비한 인력을 신속히 육성하여 생산 및 품질 조기 안정화에 기여")

## 6. 해결방안·추진내용 (How)

### 6-1. 원인–대책 대응 (공통)

- 원인별로 대응하는 조치를 하나 이상 제시한다. **원인 항목 순서와 해결방안 순서를 가능한 한 일치**시킨다.
- 대책의 조치대상과 효과를 정확히 말한다. 예: 소음 기준 정비는 '소음 발생 예방'이 아니라 '층간소음 갈등 예방 체계'의 일부(1649).
- 법률 개정, 행정 조치, 예산 투자, 캠페인 등 수단의 성격을 분명히 한다. 법률 개정이 필요한지 명확히 쓴다(1662).
- 기존 정책의 한계로 지적한 내용과 대책이 어긋나지 않게 한다(1659).
- 대책이 추가되었다면 대응하는 문제가 실제 확인됐는지 역방향으로 점검한다. **검증 항목을 찾기 위한 것**이지 원인 사실을 만들어내는 방법이 아니다.

### 6-2. 여러 부서 수합자료 정리

| 구분 | 언제 | 교정 가능 | 교정 금지 |
|---|---|---|---|
| **약편집** | 각 부서 업무 현황·실적·계획 취합 보고 | 중복 워딩, 불릿, 폰트, 선·도형, 분량 밸런싱, 작성 패턴 통일 | 핵심 내용, 품질·금액·인원 수치, 추진 일정, 투입자원 |
| **강편집** | 기획성 업무(예: 교육지원 방안 마련) | 자료 조합, 새 내용 착안·추가 | 착안 콘텐츠는 해당 부서와 협의해 실행가능성 검토 후 반영 |

**강편집 5단계** (Case B: 부서별 24줄 → 13~15줄)

1. **그룹핑**: 부서 관점을 지우고 유사성·연관성 기준 **2~3개 대상 카테고리**로 묶는다(리더십그룹·조직역량그룹 모두에 신입·직책자가 있다 → '신입·경력 / 직책자'로).
2. **정제**: 남길 범위를 **추진방향 해당 항목 1문장**으로 정한다. 범위 밖은 다른 항목으로 재배치, 주제 밖은 제거, 중복은 아무리 매력적이어도 제거.
3. **발췌**: 경영층은 늘 **News & Differences**를 원한다. 기존과 다른 콘텐츠만 본문에 남기고 나머지는 삭제하거나 첨부로.
4. **착안**: News & Differences가 없으면 5W2H, 4M1E로 구체화해 새로 착안한다.
5. **구조화**: 구체화 → 연결해 스토리 구성 → 구조화해 가독성 확보.

**News & Differences 다섯 가지 틀**

| 구분 | 유형 | 뜻 |
|---|---|---|
| News (기존에 없던 것) | ① 신규 | 기존과 별개로 새 콘텐츠 생성 |
| | ② 교체 | 기존 것을 없애고 새 콘텐츠로 |
| Differences (기존과 연계) | ① 추가 (+) | 기존에 다른 콘텐츠를 더함 |
| | ② 축소 (−) | 기존의 일부를 없앰 |
| | ③ 대체 (⎇) | 기존 일부를 없애고 다른 것으로 채움 |

- 착안 예(추가): 그룹 공통가치 교육(기존) + 밸류체인 공정 이해(추가). 그룹 공통 직책자 리더십(기존) + 신규사업 조직안정화 역량(추가).
- 카테고리마다 1줄 헤드라인: `대상 : 무엇은 같게, 무엇은 따로`
  - 신입·경력 : 그룹 공통가치 교육은 아진산업과 동일하게, 業이 다른 직무기초 컨텐츠는 별도 교육
  - 직책자 : 그룹 공통의 P·E 직군 직책자 리더십을 함양하되, 신규사업 추진 및 조직 안정화 역량을 제고

### 6-3. 새로 추진하는 업무 (신규추진 내용)

1. **큰 그림부터**: 맨 위 1줄 `요구 → 해법`으로 전체 컨셉을 먼저 보인다.
   - 이차전지소재 특화 제조공정 이론 → 「아카데미」 신설 | 공정설비 특성에 따른 기계·전기 정비 → 기술교육 과목 개편 | 밸류체인 공정 최적화 → 디지털교육 과목 개편
2. **세부는 '목적 → 구성 → 운영' 틀**로. 대상(직급별 중점교육)은 '구성'에. 하위 꼭지에 상위 장 제목과 같은 말(예: '추진방향')을 쓰지 않고, 단계를 건너뛰지 않는다.
3. **목적은 YOU 관점, Benefit으로**
   - Before) 이차전지소재 전반의 사업을 이해하고 밸류체인 공통의 직무역량을 학습하는 전문 교육 과정
   - After) 밸류체인 사업회사의 생산성·품질 향상을 리딩하는 전문인력 육성
4. **구성은 메뉴판이 아니라 Why·For what**: 직원 계층 기준으로 컨셉을 쓴다.
   - After) 직무를 처음 접하는 입문자부터 전문역량 확보를 위한 심화 과정까지 편성 → 신규자는 필수입과 (그外는 선발 입과)
   - 세부 과정은 `과정 | 입과대상 | 계층별 역량 + 학습 목표` 패턴으로. 과목표는 다음 장이나 첨부로.
5. **운영도 대상의 참여 편의 관점**: "소재사 공통 과정으로 진행하되, 집합교육 참여가 어려운 직원에게도 공평한 학습기회를 제공" ☞ "사전학습은 이러닝, 본학습은 집합+웨비나 병행, 사후학습은 LP 활용"
6. **헤드라인 ↔ 본문 키워드 일치**: 같은 키워드, 같은 순서로.
7. **'쌀로 밥을 합니다' 헤드라인 금지**: 어느 업종에나 쓸 수 있는 헤드라인은 News가 없다. **비교·관계·추세·분포·구성**에서 뽑는다. 예: "기존 아진산업 교육과정을 활용하되, 화학 기계·전기 설비 특성에 적합하게 개편하여 운영"
8. **Level 맞추기**: '운영안 / [맞춤형] / [표준교육]' → 교육유형 : 맞춤형 + 표준교육 2 Track.
9. **안내서 ≠ 보고서**: 현황만 나열한 문장은 메시지 문장으로 바꾼다.
10. **키워드에 공감 장치**: 예시(권위자 어록, VOC·VOB, 기사, 실제 Case) / 통계 / 정의(학문·법·규범) 중 하나로 받친다. (예: "신설 공장 내 2000개 이상의 CCTV와 센서 有(뉴스룸)" → 데이터 기반 최적화·자동화를 위한 뉴칼라 양성 要)
11. **덜어내기 3단계**: ① 없어도 되는 문장 제거 ② News 키워드로 정렬 ③ 구조화(텍스트 4줄 이상이면 2~3줄 단위로 쪼갬).
12. **키워드 배열 선택**: 좌우(비교) / 상하(비교 불필요; '배경 → 예시', '원인 → 결과', '현황 → 메시지' 패턴 통일) / 흐름(절차·시간 순서도).
13. 대상 차별화를 구체적으로: "회사별 개선역량에 따라 RPA 교육 차별화 — 개선경험 보유社: RPA 실습 중심 | 신규설립社: RPA 실습 + 과제발굴 + 코딩 코칭"
14. 단계적 오픈·전제조건은 하단 ※·☞로: "※ '23년은 저근속 대상 입문과정 먼저 오픈, 단계적으로 심화과정 개발"

## 7. 세부 추진계획·액션플랜 (What)

- **추진체계**: 주관·협력 주체, 역할과 의사결정 구조.
- **추진전략**: 과제에 필요한 **입법, 예산확보, 이해관계 조정, 국민/내부 소통, 사업운영** 등을 선택.
- **추진일정**: 단계, 책임 주체, 선행조건, 성과지표. 일정은 구체적으로('3, 6, 9, 12월').
- 핵심 방안이 법령 개정이면 **입법전략을 누락하지 않는다**(1666). 예산이 필요하면 예산확보 전략을 포함한다.
- 담당자, 일정, 수치가 자료에 없으면 만들지 말고 `[결정 필요]`로 표시한다.

## 8. 본문 전개 : 結·根·方·課

- **결론(뭔데?, 헤드라인) → 근거(왜 하는데?) → 방법(어떻게 할 건데?) → 효과(뭘 얻는데?)**
- 결론이 흥미로워야 본문을 읽고, 본문이 충실해야 실행에 동의한다.
- **슬라이드 하나 안에서는 두괄식**(결론이 명쾌할 때). 결론에 논쟁 여지가 있으면 근거 먼저. **보고서 전체 구성은 미괄식·양괄식·중괄식**이 선호된다(문제해결·설득·새 일 시작이 목적이면 전체 스토리라인은 미괄식).
- **응용 전개**: what · why · how · so what을 MECE 원칙 下 조합.
  - **수평 전개(another)**: 같은 스타일의 문장을 같은 Level로 나란히, 빠짐·중복 없이.
  - **수직 전개(specific)**: 키워드를 5W2H, 4M 등으로 세분화해 묶고–풀기로 상하 전개.
- 응용 패턴 예 (묶고 = 헤드라인, 풀고 = 본문):
  - Case1: what – why1 – why2 → (묶고) what – how → (풀고) specific → so what
  - Case2: what → 수직 specific what ×2 → 수평 another what → so what
  - Case3: 묶고1·풀고1 / 묶고2·풀고2 / 묶고3·풀고3 (another) → so what
  - Case4: what – why → 묶고1·풀고1(specific1) / 묶고2·풀고2(specific2) – why
  - Case5: (what – how) 묶고·풀고 × 3 (another) → so what
- 교정 시 문장마다 what / why / how / so what 중 무엇인지 표시해 빠진 요소와 순서를 진단한다. 빠진 요소는 채우되 원문에 없는 근거는 `[ ]`.

## 9. 문장 교정

- 메모·키워드 단순 나열을 논리적으로 연결된 완전한 문장으로 바꾼다(1650).
- 주어와 서술어가 호응하는지 확인한다(1656). 주어가 불명확한 문장을 고친다(1669).
- 명사–동사 결합: 수는 증가/감소, 비율은 상승/하락처럼 대상에 맞게(1656).
- 원인 → 결과 → 후속 영향의 위계를 유지한다. 직접 원인과 파생 비용을 같은 수준으로 병렬 나열하지 않는다(1669).
- 유사한 뜻의 문장·불필요한 수식어·반복 서술, 당연한 말을 줄인다(1649, 1666, Case A).
- 목차와 하위 항목의 명사형/서술형, 추상화 수준을 통일한다(1656). 같은 대상은 한 용어로.
- 느낌말('저조, 부족, 큼, 불비')은 수치나 쉬운 원인으로 바꾼다(4-4 표).
- 한 줄에 맞추려고 자간을 줄이기보다 문장을 간결하게 고친다(1677).
- 기호 체계: □ 헤드라인 → - 세부 → * 각주 → ※ 참고 → ☞ 결론.

## 10. 최종 정합성 점검

### 10-1. 매핑표 (내부 점검용, 필요하면 사용자에게도 제공)

| 문제·이슈 | 확인된 증거 | 원인/원인 가설 | 근거 수준 | 추진방향 | 해결방안·추진내용 | 필요한 실행전략 |
|---|---|---|---|---|---|---|
| [문제 A] | [자료·시점] | [원인 A] | 확인/검증 필요 | [방향 1] | [조치 A] | [입법/예산 등] |

### 10-2. 2단계 검수

**A. 내용·논리**

1. **헤드라인만 모아 읽기**: 검토배경 → 현황·이슈 → Take away → 추진방향 → 추진내용 헤드라인이 한 이야기로 읽히는가. 섬처럼 끊기는 곳을 표시한다.
2. **질문 ↔ 답 대응**: 각 문제·이슈에 대응하는 대책이 있는가. 답 없는 질문, 질문 없는 답은 없는가. 순서·번호가 같은 행에 붙어 있는가.
3. 자료로 입증되지 않는 문제를 단정하지 않았는가. 원인은 **어떤 문제의** 원인인지 분명하고 서로 중복되지 않는가.
4. 법률·예산·조정·소통이 필요한 대책이 추진계획에 반영됐는가.
5. I 관점 용어가 남아 있지 않은가. I 관점이라 빠진 영역은 없는가.
6. 장 제목이 내용과 맞는가.

**B. 문장·표현**: 주술 호응, 인과관계, 모호한 대상, 어휘 결합, 중복, 병렬 항목의 Level·패턴·색, 과장·느낌말, 단위·기준시점.

**C. 분량**: 장표당 13줄 내외(1131 × 2), 도표 항목 3~4개, 텍스트 4줄 이상 덩어리 없음.

수정 사유는 '단순 취향' 대신 **문제 → 이유 → 수정안**으로 제시한다. 자료상 결함이 확인되지 않은 부분은 임의로 수정하지 않는다.

### 10-3. 자기점검 체크리스트

- [ ] 제목만 읽고 대상·목적·조치 방향이 명확한가?
- [ ] 검토배경에 '왜 중요한가'와 '왜 지금인가'가 각각 있는가?
- [ ] 검토배경의 핵심 주장이 실태분석·현황에서 입증되는가?
- [ ] 현황은 제목·독자 관심과 직접 관련되며, 문제는 상태 차이로 정의되어 있는가?
- [ ] 증가·감소 등 수치 주장은 검증 가능한 근거가 있는가?
- [ ] 원인은 해당 문제의 원인이고, 상호 중복되지 않는가?
- [ ] 추진방향 헤드라인이 Take away에 답하고, 뇌리에 남을 키워드가 있는가?
- [ ] 대책·추진내용은 이슈·원인과 같은 순서·대상으로 대응하는가?
- [ ] 법 개정·예산·협의가 필요한 대책은 추진전략에 반영됐는가?
- [ ] 헤드라인이 '쌀로 밥' 문장이 아니라 News & Differences를 담고 있는가?
- [ ] 문장에 주어·서술어·조사가 필요한 만큼 있으며 인과관계가 맞는가?
- [ ] 항목의 표현·Level이 일관되고, 반복·군더더기가 제거됐는가?
- [ ] 출처 없는 수치·확정되지 않은 가설·개인정보가 출력되지 않았는가?

## 11. 출력 형식

사용자가 별도 양식을 지정하지 않으면 다음을 따른다.

**신규 작성 시** (Raw 자료·메모 → 보고서)

```
① 핵심 요약: 해결할 문제, 핵심 근거, 판단·결정이 필요한 사항
② 장 구성안 (문제해결형 / 추진방안형 / 혼합)과 고른 이유
③ 그대로 붙여 넣을 초안 (장마다 헤드라인 + 본문, □ → - → * → ※ → ☞)
④ 문제·이슈 → 원인 → 대책·추진내용 대응표
⑤ 확인 필요 사항 ([ ]로 비운 수치·사례·인용, 가정한 독자·보고 성격)
```

**교정 시**

```
1. 핵심 요약: 논리 오류와 수정 우선순위
2. 장(章)마다:
   ### II. 현황 및 이슈 (장 제목)
   **교정의견**
   1. "원문 인용" → 문제 유형(장 제목 불일치/중요성·시급성 없음/근거 없는 수치/문제·원인 혼재/원인 중복/
      원인–대책 불일치/입법·예산 전략 누락/스토리 단절/현황만 있음/느낌말/의미 중복/I 관점/Level 불일치/
      키워드 불일치/쌀로 밥 헤드라인/안내서식 나열/색 남용/연결 대상 분리/주술 호응 등)
      → 이유 → 수정 방향
   **After**
   (수정한 헤드라인·본문)
   — 또는 간단한 교정이면 원문 / 문제점 / 수정문 / 수정 이유 비교표
3. 헤드라인만 모은 스토리 한 줄 (Before → After)
4. 문제·이슈 → 대책 대응표
5. 전체 수정본(요청 시), 추가 입증에 필요한 데이터 목록, 최종 체크리스트
```

**부분 요청 시**: 한 장만 주면 해당 장의 원칙만 적용하고, 앞뒤 장과의 연결이 필요한 부분(Take away, 대응표)은 "앞뒤 장을 주면 아귀를 맞춰 드림"으로 짧게 안내한다.

**자료 오탈자 유의**: 1662 사례의 원문/수정문 비교표에는 다른 사례의 제목이 들어간 것으로 보이는 부분이 있다. 이를 교정 기준으로 전용하지 않고 본문 코멘트와 나머지 항목을 우선한다.
