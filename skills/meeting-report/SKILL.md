# 회의결과 보고서 작성 스킬

회의 메모·녹취·회의록 초안을 회의결과 보고서로 정리하거나 교정할 때 쓰는 스킬이다. 교안 [부록2] 「회의결과 작성 Tip」의 원칙과 Case Study(비대면 교육운영 간담회 결과 보고: 회의내용 → 단락 나누기 → 초안 → 교정의견 → 수정후)를 정리했다.

보고서 일반 방법론(독자 니즈, 메시지 도출, 묶고–풀기, 문장 교정, 1-page 양식 등)은 `koreport-skill`을 따른다. 이 스킬은 그 위에 **회의결과 보고에 특화된 것**만 얹는다.

**핵심 한 줄: 회의 개요 → 주요 발언내용 → 향후 계획. 용어는 회의 유형에 맞게 바꾼다.**

회사 업무에서 "의견을 듣기만 하는" 회의는 없다. 반드시 어떤 문제를 개선·해결하는 것이 일이므로, 회의결과에는 **발언을 어떻게 처리·개선하겠다는 내용(향후 계획)**이 꼭 들어가야 한다.

---

## 0. 작업 순서

1. **회의 유형 판단 (1장)**: 정보공유 / 의견수렴 / 의사결정 중 무엇인지 먼저 정한다. 사용자가 밝히지 않았으면 내용으로 추정하고, 추정했다고 밝힌다.
2. **회의내용 정리 (Step1)**: 회의 목적과 내용을 형식에 구애받지 않고 빠짐없이 모은다.
3. **단락 구분 (Step2)**: 유사성·연관성·특징으로 덩어리 짓고 덩어리마다 키워드로 이름 붙인다.
4. **스토리 구성 (Step3)**: 덩어리를 회의 개요 / 회의결과 / 향후계획에 배치한다.
5. **초안 작성 (Step4)**: 質보다 量. 빠짐없이 빨리 쓴다.
6. **교정·교열·윤문 (Step5)**: 4장 체크리스트로 고치고, 참석자와 확인할 곳을 표시한다.

## 1. 회의 유형별 보고 내용

| 유형 | 1) 회의 개요 | 2) 본문 (용어) | 3) 향후 계획 |
|---|---|---|---|
| **의견수렴 회의** | 목적/배경(필요시), 일시·장소·참석자, 회의 안건, 그간의 추진경과(필요시) | **수렴 결과** : 안건(또는 이슈)별 의견 | 의견별 실행방안 (추진계획, 주관부서, 일정 등) |
| **의사결정 회의** | 목적/배경(필요시), 일시·장소·참석자, 의사결정 안건, 그간의 추진경과(필요시) | **주요 발언내용** : 참석자(또는 관련부서) 의견 | 의사결정에 따른 예상 전망, 문제점 및 해결방안 |
| **정보공유 회의** (산업 트렌드, 신기술·노하우 공유) | 목적/배경(필요시), 일시·장소·참석자, 공유 정보 요지 | **공유 내용** : 세부 공유 내용 | 업무활용 방안, 한계점 보완 방안(필요시) |

- 기본 흐름은 **회의 개요 → 주요 발언내용(또는 회의 결과) → 향후 계획(또는 조치 방안)**이다. 제목 용어만 유형에 맞게 바꾼다.

## 2. 회의결과 보고서 Flow

### 2-1. 회의 개요
- **목적/배경(필요시)** : 왜 지금 회의를 여는가. 중요성과 시급성을 언급한다.
- **일시/장소** : 년.월.일(요일) 시간 / 구체적인 장소. 예) `'22.11.08(화) 10:00~13:00 / 정도관 302호`
- **참석자** : 부서와 직급, 담당업무를 표기한다. 총원과 구성을 함께 쓴다. 예) `총 6명 (그룹사 HRDer 3, 인창원 교육운영자 3)`
- **회의 주제** : 어떤 주제에 대해 의견을 수렴하거나 의사결정할지, 무엇을 공유할지.
- **추진경과(필요시)** : 이번 회의 전까지 전개된 주요 히스토리를 나열한다.
- **진행 순서** : 회의 일정·프로그램은 본문이 아니라 **개요 안에 1~3줄**로 모은다.

### 2-2. 주요 발언내용 (회의 결과)
- 발언내용이나 결정사항을 종합 → **중복 없이 그룹핑** → 개조식으로 정리한다.
- 그룹 이름은 발언 주체나 주제 키워드로 붙인다. 예) `교육생 / 강사`, `LP 활용 / 강사 응대`
- 발언은 **들은 소리(모니터링 결과·현황) → 건의사항** 순으로 놓는다.
- 발언에 나온 수치 근거는 해당 덩어리 바로 아래 `※`로 붙인다. 예) `※ 뉴칼라 교육내용 질문 : LP에 1일 약 40건, 웨비나 수업 중 채팅질문은 과정당 약 150건`
- 참석자별 발언 전문은 본문에 넣지 않고 **첨부**로 돌린다.

### 2-3. 향후 계획 (조치 방안)
- 회의결과에 대한 실행방안을 도출한다: **무엇을, 누가(주관부서), 언제까지**.
- **건의사항마다 처리 방향을 1줄씩** 대응시킨다. 담당·기한이 녹취에 없으면 `[확인 필요]`로 남긴다.
- 의사결정 회의는 결정에 따른 예상 전망, 문제점과 해결방안을 쓴다.
- 정보공유 회의는 업무활용 방안, 한계점 보완 방안을 쓴다.
- 조치 성격별로 묶으면 읽기 쉽다. 예) `시스템 / 절차 / 변화관리`

## 3. 작성 5단계

| 단계 | 할 일 |
|---|---|
| **Step1. 회의내용 정리** | 회의 종료 후 빠른 시간 內에 참석자 발언, 공유 정보 등을 빠짐없이 정리. 형식에 구애받지 않고 충실하게 서술 |
| **Step2. 단락 구분** | 회의 현황·내용을 유사성·연관성·특징 기준으로 덩어리 짓기 → 각 덩어리를 대표하는 키워드로 네이밍 → 유사 내용 통합, 중복 제거, 계층화해 흐름에 맞게 재배열 |
| **Step3. 스토리 구성** | '회의개요'에 목적·일시·장소·참석자·주제, '회의결과'에 의견수렴·의사결정·정보공유 내용, '향후계획'에 추진 방안과 일정 |
| **Step4. 초안 작성** | 質보다 量 중심으로 세 덩어리를 빨리 작성. **사실과, 사실로부터 도출한 의견을 명확히 구분**. 진행 중·완료·계획 등 **시제를 명확히** |
| **Step5. 교정·교열·윤문** | 참석자와 함께 빠진 내용은 없는지, 도출한 이슈는 정확한지, 개선방안은 타당한지 토의. 독자 관점에서 읽기 쉽게·정확하게·간결하게. 설명 없이 소리 내어 읽어 어색함이 없는지 재확인 |

## 4. 교정 체크리스트 (회의결과 특화)

1. **단락 제목과 내용이 맞는가?** 제목은 "주요 일정"인데 내용은 "교육생과 강사의 소리"면 매칭이 안 된다. 일정은 개요로, 발언은 주요 발언내용으로 옮긴다.
2. **스토리가 보이는가?** "회의 개요 → 주요 일정 → 논의 사항"은 회의를 시간순으로 옮긴 것일 뿐 스토리가 없다. "회의 개요 → 주요 발언내용 → 향후 계획"으로 재구성한다.
3. **향후 계획이 있는가?** 없으면 회의를 왜 했는지 드러나지 않는다. 건의사항마다 조치를 대응시킨다.
4. **일정이 본문을 차지하지 않는가?** 2쪽 보고서에서 "주요 일정"이 1쪽을 차지하면 비중이 뒤집힌 것이다. 진행 순서는 개요 1~3줄로 줄인다.
5. **사실과 의견이 섞이지 않았는가?** 들은 소리(사실)와 건의(의견), 작성자 해석을 구분한다.
6. **문장 종결 패턴이 통일됐는가?** "불만을 제기하기도 함" 같은 만연체·음슴체와 "러닝플랫폼 개선방안 논의" 같은 명사 종결이 섞이면 정리가 덜 된 느낌을 준다. 한 호흡으로 읽히는 문장으로 패턴을 맞춘다.
7. **수치가 서로 맞는가?** 개요의 참석자 수(초안 "총 9명")와 실제 구성(3+3=6명)처럼 어긋나면 임의로 고치지 말고 표시해 확인을 요청한다.
8. **잡담·중복 발언을 지웠는가?** 오찬 중 토론 같은 곁가지는 진행 순서 1줄로만 남기거나 지운다. 녹취에 없는 내용은 쓰지 않는다.

## 5. Case Study : 초안 → 수정후

비대면 교육운영 간담회 결과 보고(실장 보고용).

| 구분 | 초안 | 수정후 |
|---|---|---|
| 구성 | 1. 회의 개요 / 2. 주요 일정 / 3. 주요 논의사항 | 1. 회의 개요 / 2. 그룹사 HRDer 주요 발언내용 / 3. 향후 개선 계획 |
| 개요 | 일시·장소·참석자만 (참석자 "총 9명") | **목적**(비대면 교육운영 이슈 파악 및 개선의견 도출) 추가, 일시/장소 한 줄, 참석자 "총 6명 (그룹사 HRDer 3, 인창원 교육운영자 3)", **진행 순서**(웨비나 체험 / 웨비나 모니터링 / 간담회) 3줄 |
| 발언내용 | "주요 일정" 아래에 교육생·강사 인터뷰 내용이 시간순으로 길게 섞임 | ○ 교육과정 모니터링 결과 (교육생 / 강사) + ※ 수치 근거 → ○ 건의 사항 (LP 활용 / 강사 응대). 건의마다 "→ 조치 필요" 형태 |
| 향후 계획 | 없음 | 헤드라인: "간담회에서 논의한 모니터링 결과와 건의사항은 ○○○부에서 11월 內 조치" → 시스템 / 절차 / 변화관리별 조치·일정 1줄씩 |
| 문장 | 만연체·음슴체·명사 종결 혼재 | 개조식, 종결 패턴 통일 |

수정후 향후 계획 예시:
```
3. 향후 개선 계획
 ○ 간담회에서 논의한 모니터링 결과와 건의사항은 ○○○부에서 11월 內 조치
   [시스템]   '딜레마해결' 채널 내 '컴퓨터비전' 질의응답 코너는
              → 러닝플랫폼 4분기 개편시 ICT에 신설 요청
   [절차]     담당교수 부재시 대기, 웨비나 교육 중 질의에 대한 응답 문제는
              → 인창원 교수 워크숍을 통해 11월 內 개선안 도출
   [변화관리] 인창원 교수의 교육생 상담, 질의응답 관련 CS마인드 향상은
              → 11.21(월) 외부 전문 CS강사를 초빙하여 4시간 교육 실시
```

## 6. 주의

- 인사·계약·미공개 실적이 오간 회의는 사내 승인 도구에서만 정리하도록 안내한다.
- 녹취·메모에 없는 결정, 담당자, 기한을 지어내지 않는다. 빈 곳은 `[확인 필요]`.

## 7. 출력 형식

**작성 요청 시**
```
① A4 1장 회의결과 보고서 (제목 / 1. 회의 개요 / 2. 주요 발언내용(유형별 용어) / 3. 향후 계획)
② 참석자와 확인할 곳 (빈 담당·기한, 수치 불일치, 사실/의견 구분이 모호한 발언)
③ 판단한 회의 유형과 근거 1줄 (사용자가 지정하지 않았을 때)
```

**교정 요청 시**
```
**교정의견**
1) 덩어리(구성·스토리) : 단락 제목–내용 매칭, 흐름, 향후 계획 유무
2) 단어와 문장 : 종결 패턴, 사실/의견, 시제, 중복
**After**
(수정한 보고서)
```
