# 주간업무 실적·계획 작성 스킬

주간업무 실적·계획(주간보고)을 쓰거나 교정할 때 쓰는 스킬이다. 교안 [부록1] 「주간업무실적과 계획작성 Tip」의 원칙과 Case Study(4분기 뉴칼라 레벨2 인증시험 결과 보고: 원자료 → 초안 → 수정의견 → 수정후)를 정리했다.

보고서 일반 방법론(독자 니즈, 메시지 도출, 묶고–풀기, 문장 교정, 1-page 양식 등)은 `koreport-skill`을 따른다. 이 스킬은 그 위에 **주간보고에 특화된 것**만 얹는다.

**핵심 한 줄: 내가 한 일이 아니라, 고객(의사결정자·임원)이 알아야 할 것을 쓴다.**

---

## 0. 작업 순서

1. **관점 전환 (I → You, Reader First)**: 독자(팀장·임원)가 누구이고 무엇에 관심 있는지 먼저 확인한다. 사용자가 알려주지 않았다면 "임원 관심사 / 부서 KPI"를 물어보거나, 모르면 가정을 밝히고 진행한다.
2. **'깜' 선별 (1장)**: 이번 주 한 일 가운데 보고할 항목만 고르고, 나머지는 뺀다. 뺀 항목과 이유를 따로 알려준다.
3. **흐름 잡기 (2장)**: 항목마다 배경 → 현황 → 이슈 → 방안 중 필요한 것만 골라 조합한다.
4. **News & Differences 찾기 (3장)**: 지난주와 이번 주, 전분기와 이번 분기 사이에 무엇이 달라졌는지 하나라도 메시지로 만든다.
5. **초안 작성 (4장 양식)**: 헤드라인(묶기) → 본문(풀기) 구조로 쓴다.
6. **교정·교열·윤문 (5장 체크리스트)**: 초안을 쓴 뒤 8가지 관점으로 다시 고친다.

## 1. 보고할 '깜'인가? (선별 기준)

아래 중 하나 이상에 해당해야 주간보고에 올린다. 해당 없는 항목은 과감히 뺀다.

1. 고객(임원)이 **지시한 사항, 관심 사항**인가?
2. 부서의 **실행전략·KPI와 연계**되고, 고객에게 자랑할 만한 내용인가?
3. 고객의 의사결정이 필요한 **인력·비용(수익)·시간** 등 리소스 투입·관리 이슈인가?
4. 고객이 **타부서·계열사·지주사 임원과 소통할 만한** 깜이 되는 내용인가?
5. **지주사·CEO의 지시, 관심, 전략**과 연계된 내용인가?

- 일정은 **직책자·임원이 꼭 알아야 할 일정**만 쓴다. 내 업무 일정(명단 송부 → 확정 → 발표 같은 실무 절차)은 필요 없으면 뺀다.
- 임원에게 공유하기에 **너무 가벼운 주제**(예: 시험장 부정행위 방지를 위한 좌석 배치)는 뺀다. 덜 중요한 것을 지워야 중요한 것이 부각된다.
- 고객이 알아야 할 이슈를 찾을 때 쓰는 「생각의 끈」
  - 고객과 「고객의 고객」의 관심사: 인력·비용·시간 등 투입 리소스 내실화, CEO 보고깜, 지주사·그룹사 협의사항
  - 최근 지주사·그룹 이슈 (예: 수해복구, 신사업 리스킬링)
  - 기획 프레임: QCD(만족도·비용·시간), 교육체계–과정–과목–교재–운영, KSA(Knowledge·Skill·Attitude), 4M(Man·Machine·Material·Method), 5W1H, PDCA, 증가·창조·제거·감소

## 2. 주간보고 Flow : 배경 → 현황 → 이슈 → 방안

| 단계 | 쓰는 내용 | 작성 요령 |
|---|---|---|
| **배경 (Why)** | 중요성과 시급성 | 배경 문장 뒤에 "~가 중요" 또는 "~가 시급"을 붙여 말이 되는지 확인. 고객이 배경을 잘 알면 생략. 검토배경은 의사결정을 받을 때, 추진배경은 결정된 일의 중요성·시급성을 되짚을 때 |
| **현황** | 고객이 알아야 할(관심 있는) 사실·데이터 요약 | 백화점식 데이터 나열 금지. 메시지(이슈·방안)의 근거가 되는 디테일만. 3개 정도 덩어리로, 도표는 항목 5개 이내 |
| **문제점·원인 (이슈)** | 현황 분석으로 발견·유추한 인사이트, 2차적 사실 = 고객에게 전달할 메시지 | 내용이 많으면 문제점과 원인을 분리. 단순하면 한 문장에 녹이되 문장 패턴 통일 |
| **개선방안** | 이슈 해결·조치 방안, 향후 추진 일정 | 순서대로 나열. 필요하면 소요예산, 행정사항, 협업사항, 기대효과 병기 |

- 보고 목적에 맞게 **흐름을 조합하고 용어를 바꾼다.** 조합 예: ① 현황 ② 현황 – 이슈 ③ 현황 / 문제점 – 방안 ④ 배경 – 현황 – 이슈 – 방안. 결과 보고라면 **결과 – 이슈 – 조치방안**.
- 배경·현황·이슈·방안에 **하나의 테마**가 흐르게 하고, 곁가지는 모조리 지운다.
- **직원은 현황을 보지만, 고객은 메시지에 관심이 있다.** 현황만 나열하고 끝내지 말고, 문제점·원인과 개선방안을 메시지로 뽑아 준다.

| 현황 (직원의 시선) | 문제점·원인 (메시지) | 개선방안 (메시지) |
|---|---|---|
| ○ 일시 : '22.10.25 ○ 장소 : 포항, 광양, 서울 ○ 인원 : 327명(응시율 72%) ※ 3분기 82% ○ 언어 : R 3명, 파이썬 324명 ○ 합격 : 102명(합격률 31%) ○ VOC : 시험이 예상보다 어려움 | ○ 수해복구로 응시율 72%, 3분기 82% 比 10%p 하락 ○ R 응시자는 3명에 불과, '22년 교육참여자도 5명 | ○ 수해복구로 미응시한 직원은 응시제한 한시적 해제 ○ R 과정은 6 → 2차수로 조정, 축소한 4차수는 파이썬으로 대체 |

## 3. 이슈와 방안 도출 : 관찰 → 고찰 → 통찰

지난주와 이번 주는 무엇이 **News & Differences**인가? 하나라도 이런 포인트를 찾아 표현한다.

1. **관찰 (Facts & Data 조사·분석)**
   - 수집한 자료에서 **핵심 변수만** 고른다. (예: 니즈가 '제조공정 품질개선'이면 공정유형·불량·수율 3개만)
   - 변수를 x–y 매트릭스로 조합한다. (예: 반응 × 불량, 소성 × 수율)
   - 수치는 Roll up·피벗으로 요약하고 합계·차분·증감으로 정보화한다. 필요하면 막대·선·파이·산점도·히스토그램으로 본다.
2. **고찰 (Changes 발견)** : 다섯 가지 렌즈로 본다.
   - ① **비교**: 평균, 최대, 최소, 전후, 지표
   - ② **트렌드**: 증가·감소, 상승·하락, 사이클, 유지
   - ③ **구성**: 전체 항목의 빈도, 크기 순서
   - ④ **분포(비율)**: 주로 어디에 분포하나, 어디가 특이한가
   - ⑤ **관계**: 상관관계, 원인과 결과
3. **통찰 (Issue와 Recommend 도출)** : 고객 관심 분야의 변화 포인트를 메시지로 만든다.

사용자가 표·수치를 주면 다섯 렌즈별로 메시지 후보를 한 줄씩 뽑아 보여주고, 그중 고객 관심사에 맞는 것을 헤드라인으로 고른다. (교안 실습: 10년간 A~E소재 매출 표에서 비교·트렌드·구성·분포·관계별 메시지 도출)

## 4. 작성 양식과 원칙

### 4-1. 헤드라인 ↔ 본문은 '묶고 → 풀기'
헤드라인은 본문을 묶고(결론), 본문은 헤드라인을 푼다(근거). 또는 풀고 → 묶는다. 이 원칙을 철저히 지킨다.

```
‘22년 4분기 뉴칼라 레벨2 인증시험 실시 결과 (10.xx 시험, 11.x 합격자 발표)
 □ 시험결과 : 시험신청 xxx명 中 xxx명이 응시하여 xx명이 합격(xx.6%, 3분기 xx.4%)
 □ 이슈사항 : 합격률은 전분기와 유사하나, 응시율 저하 및 R언어 선택 저조      ← 묶기
   - 응시율 : 수해복구 관련 응시자 감소로 응시율 71.9%(3분기 81.8% 比 10%p ↓)  ← 풀기
       ※ 3분기 比 응시인원 : 포항 13x명 → 8x명, 광양 8x명 → 8x명, 서울 3x명 → 2x명
   - 응시언어 : R 3명(포 2명, 광 1명), 파이썬 xx명, 워크벤치 xxx명
       ※ ‘22년 Lv1·2 집합교육 실적 : R 5명, 파이썬 xxx명, 워크벤치 xx명
 □ 조치방안
   - 포항 未응시자는 차기 시험 응시제한 패널티 한시 未적용(‘23년 1분기 시험 응시 가능)
   - 시험응시·교육참여가 낮은 R 과정은 ‘23년 집합교육을 年 2차수만 운영(‘22년 x차수)
       → 축소한 4차수는 수요가 많은 그룹사 또는 파이썬 교육으로 전환 검토
```

### 4-2. 항목 구성
- 항목이 5개 이상이면 무엇이 현황이고 무엇이 이슈인지 한눈에 안 들어온다. **3개 덩어리**(예: 시험결과 – 이슈 – 조치방안)로 묶는다.
- **이슈는 한 곳에 모은다.** "※ 응시율 저하 원인", "※ 합격률 저하 원인"이 결과 아래 흩어져 있는데 "주요 이슈사항"이 또 나오면 독자가 헷갈린다. 이슈 결론 1줄을 먼저 쓰고 그 아래 푼다.
- 같은 성격의 꼭지(VOC 등)가 두 번 나오지 않게 한다.
- **조치방안은 이슈와 1:1**로, 무엇을·언제부터를 구체적으로 쓴다.
- 결과 1줄은 **신청 → 응시 → 합격(률, 직전 기간 比)**처럼 흐름 한 줄로 요약한다.

### 4-3. 수치와 비교
- 수치에는 **비교 기준**(전주·전분기·목표·계획)을 붙인다. 사용자가 준 수치만 쓰고, 없는 수치를 만들지 않는다. 비어 있으면 `xx`로 남기고 확인을 요청한다.
- 비교는 **같은 기준끼리**. "4분기 응시율 71.9%" 옆에 "응시자 평균 131명"을 대면 호응하지 않는다. 분기 대 분기로 맞춘다.
- 비율의 차이는 **%p**. "6.2% 하락"이 아니라 "6.2%p 하락". 이런 디테일이 보고서 신뢰도를 정한다.
- 수식·부연 관계는 **바싹 붙인다**. "R 응시인원 3명"과 "(1.6%, 포항 2명, 광양 1명)", "R 5명"과 "교육수강 인원도 저조"처럼 부연이 멀리 떨어지지 않게 한다.

### 4-4. 원인과 메시지
- **원인과 결과를 가른다.** "수해복구 돌발로 당일 취소 불가피"에서 '당일 취소 불가피'는 교육생 입장의 결과다. 원인은 "수해복구 돌발"뿐이다.
- **당연한 말, 메시지 없는 VOC는 뺀다.** "시험 준비가 부족해서 합격률이 낮았다"는 메시지가 없다. 근본원인을 더 파거나, 전달할 메시지가 없으면 삭제해 흐름을 부드럽게 한다.
- **오해를 부르는 말은 쉬운 말로**. "최종 응시인원"(→ 최초는?), "가채점 결과"(→ 본 채점은?)처럼 궁금증을 낳는 말 대신 "응시인원", "채점결과"로 쓴다.

## 5. 교정·교열·윤문 8원칙 (초안 작성 後)

1. **'깜'이 되는가?** 1장의 다섯 기준으로 다시 거른다.
2. **News & Differences가 있는가?** 비교·추세·관계·구성·분포 중 하나라도 고객이 흥미로워할 메시지를 만든다.
3. **묶고 → 풀기를 지켰는가?** 헤드라인이 본문을 포괄하고, 본문이 헤드라인을 뒷받침하는가.
4. **말로 설명하지 않아도 이해되는가?**
   - 새로 나온 용어는 먼저 고객 눈높이로 정의한 뒤 내용을 전개한다.
   - 축약어는 고객이 이미 알아도 풀스펠링을 쓴다.
   - 주어, 주술관계, 시제, 인과관계, 앞뒤 정합성, 흐름을 확인해 **오탈문**을 막는다. 오타는 용서받아도 오탈문은 무지·불성실·무능력으로 보인다.
5. **키워드를 왼쪽에 둔다.** 고객의 시선이 처음 닿는 문장 앞쪽에 키워드를 배치한다. 너무 어색하면 재배열한다.
   - 前) 현장 제어모델 업무에 바로 활용 가능한 콘텐츠로 제어 맞춤형 커리큘럼을 구성
   - 後) **제어 맞춤형 커리큘럼은**, 현장 제어모델 업무에 바로 활용 가능한 콘텐츠로 구성
6. **중복 워딩·중복 의미를 모조리 지운다.** 글이 길어지고 주술관계가 흐려진다.
   - ① 다듬을 생각 말고 중복은 하나만 남기고 무조건 지운다 → ② 남은 말로 문장을 재구성 → ③ 소리 내어 읽어 자연스러운지 확인 → ④ 부자연스러우면 그때 중복어를 다시 넣는다.
7. **형용사·부사·관념어를 배제한다.** 읽는 사람마다 다르게 해석한다. 주간업무는 '쓰는' 게 아니라 글자로 '그린다'.
   - '매우, 극히, 저조, 우수' → 수치로. 예) "R 응시자 매우 저조" → "R 응시자는 단 3명" (저조하다고 느끼는 건 독자의 몫)
   - '객관적, 효율성, 최적화, 현장' → 이미지가 떠오르는 명사·동사로. 예) "현장 의견수렴, 토의" → "소성공정 업무전문가와 직책자 FGI"
8. **한 줄의 반도 못 채운 문장은 2/3 이상 채운다.** 덜 쓴 듯, 생각이 부족한 듯, 성의 없는 듯 보인다.
   - ① **구체화**: 키워드를 5W2H(빈도·양, 장소, 주체, 방법, 하위내용)로 세분화. 예) "○○소재실 교과목 도출 결과 보고" → "193개 과목을 직무별로 매칭한 「교과목 체계」와 「과목별 학습 안내서」를 작성 → ○○○실장에게 전달"
   - ② **추가**: 배경, 목표, 목적, 수단, 원인, 결과를 덧붙인다. 예) "○○소재 제조 및 리사이클링으로 Value Chain 확대" → "○○소재 경쟁력 확보를 위해 리튬·니켈부터 ○○·○○ 생산 및 리사이클링까지 Value Chain 확대"
   - ③ **일치화**: 묶고–풀기를 재점검해 빠진 핵심 내용을 채운다.

## 6. Case Study : 초안 → 수정의견 (교정 패턴)

교안의 인증시험 결과 보고 초안에 달린 수정의견 11개. 주간보고 교정 시 같은 유형을 찾는다.

| # | 초안의 문제 | 수정 방향 |
|---|---|---|
| 1 | 항목 5개로 현황·이슈·메시지가 한눈에 안 보임 | 시험결과 – 이슈 – 조치방안 3덩어리 |
| 2 | "최종 응시인원", "가채점" → 최초는? 본 채점은? | "응시인원", "채점결과" |
| 3 | 원인(※)이 결과 아래 흩어져 있고 "주요 이슈사항"이 또 있음 | 이슈를 한 곳에 모음 |
| 4 | "수해복구 돌발로 당일 취소 불가피" — 결과를 원인에 섞음 | 원인은 "수해복구 돌발"만 |
| 5 | 4분기 응시율 vs 응시자 평균 — 기준 불일치 | 분기 대 분기로 통일 |
| 6 | "6.2% 하락" | "6.2%p 하락" |
| 7 | "준비 없이 응시해 합격률 저조" — 당연한 말 | 근본원인을 더 파거나 삭제 |
| 8 | VOC가 두 곳에 등장, 내용도 메시지 없음 | 통합하거나 삭제 |
| 9 | "매우 저조"(작성자의 느낌), 부연 설명이 멀리 떨어짐 | 수치만 남기고, 부연은 바싹 붙임 |
| 10 | 부정행위 방지 좌석 배치 — 임원 공유엔 가벼움 | 삭제해 중요 주제 부각 |
| 11 | 금주 추진사항에 실무 일정 나열 | 임원이 알아야 할 일정만, 불필요하면 삭제 |

## 7. 원자료 → 주간보고 변환 절차

사용자가 서술형 원자료(회의록, 메모, 이메일, 실적 나열)를 주면:

1. 관찰: 일시·인원·수치·VOC·의견·일정을 뽑아 목록화한다.
2. 고찰: 직전 기간·목표와 비교해 달라진 점(Changes)을 찾는다.
3. 통찰: 이슈 결론 1줄과 이슈별 조치 1:1을 정한다.
4. 1장 기준으로 깜이 안 되는 내용(가벼운 주제, 실무 일정, 메시지 없는 VOC)을 뺀다.
5. 4장 양식으로 **헤드라인 1줄 + 결과·이슈·조치 세 덩어리**로 쓴다.
6. 5장 8원칙으로 교정한다.
7. 원자료 안의 수치가 서로 맞지 않으면(합계, 인원, 비율) 임의로 고치지 말고 표시해 확인을 요청한다.

## 8. 출력 형식

**작성 요청 시**
```
① 그대로 보낼 주간보고 초안 (항목마다 헤드라인 + 2~3줄)
② 뺀 항목과 이유 (1장 기준 중 무엇에 안 맞는지)
③ 확인 필요 사항 (빈 수치, 수치 불일치, 가정한 독자 관심사)
```

**교정 요청 시** 항목마다:
```
### 항목 n : (제목)
**수정의견**
1. "원문 인용" → 문제 유형(깜 아님/흐름/묶고–풀기/기준 불일치/%p/원인·결과 혼동/형용사·관념어/중복/짧은 문장 등)
   → 수정 방향
**After**
(수정한 헤드라인과 본문)
```
마지막에 전체 공통 지적을 3줄 이내로 요약한다.

**매주 같은 형식 유지**: 사용자가 반복 사용할 경우 위 출력 형식과 불릿 체계(□ 헤드라인 → - 세부 → ※ 참고 → → 조치)를 매주 동일하게 적용해 주간보고 형식이 저절로 통일되게 한다.
